# お庭（起床テラリウム）仕様 — Phase 0.5

`MVP_SPEC.md` の続き。設計原則（企画書・README）は常に優先。

## 0. 目的とスコープ

**日々の起床の積み重ねを「眺められる箱庭」として可視化する。** 参考イメージは「ハローキティ ドリーミーテラリウム」（ガラス容器の中に植物・小物・住人を飾る箱庭）。ただしスタミナ・ルーレット・広告視聴といった仕組みは一切取り込まない。

今回作るもの：

1. 下タブ3つのナビゲーション：**アラーム**（ホーム、既存の Home 画面）／**お庭**／**ウォレット**（既存の Wallet と Settings をまとめる）
2. お庭画面：ガラス容器のテラリウム表示、配置済みアイテム、住人（おじさん）、積み重ねの帯
3. 模様替え（編集モード）：手持ちアイテムをドラッグで配置・移動・しまう
4. 積み重ねの可視化：**連続起床日数で育つ植物**、**寝坊回数で豪華になるおじさんの小屋**
5. アイテムの入手は**仮実装**：「種屋」画面でご褒美トークンと交換できるだけ。入手方法は今後ゲーム性のある仕組みに差し替える前提なので、入手ロジックは1か所（`ItemSource` 相当）に閉じ込め、UI と分離する

作らないもの：本格的なイラスト（すべてプレースホルダー：単色図形・絵文字・簡易な `CustomPainter`）、他ユーザーの訪問、アニメーションの凝った演出、アイテムの入手ゲーム。

## 1. ドメインモデル

```
GardenItemDef（アイテム定義。コード内の静的カタログ）
  id: String                // 'plant_moss', 'bench_wood', 'lamp_small' ...
  name: String              // 表示名（日本語）
  category: plant | furniture | deco
  size: (w, h) in grid cells
  growable: bool            // 連続起床で成長するか（植物のみ true）
  costTokens: int?          // 種屋での価格。null は入手不可（配布のみ）

GardenPlacement（配置済みアイテム）
  id: String
  itemId: String
  x, y: int                 // グリッド座標（左下原点、地面レイヤー）
  placedAt: DateTime
  growthStage: int          // 0..3（植物のみ使用）

GardenInventory
  owned: Map<String itemId, int count>   // 未配置の手持ち

GardenState
  placements: List<GardenPlacement>
  inventory: GardenInventory

Streak（積み重ね。既存のセッション履歴から純粋関数で導出し、永続化しない）
  currentStreakDays: int    // 直近の連続起床成功日数（覚悟の有無を問わず、その日の全セッションが success）
  bestStreakDays: int
  totalSuccessDays: int
```

既存の `OjisanState.totalOversleeps` をおじさんの小屋の段階に使う。

## 2. 純粋ロジック（単体テスト必須）

- `computeStreak(sessions, today)`：日単位で判定。1日に複数セッションがあれば全部 success の日だけ成功日。セッションがない日はストリークを途切れさせない（アラームを設定しなかった休日で0に戻さない）。ただし failed が1つでもあれば途切れる。
- `growthStageFor(placement, streakDays)`：植物の成長段階。配置日からの連続起床日数で 0（芽）→ 1（若葉、3日）→ 2（つぼみ、7日）→ 3（開花、14日）。ストリークが途切れたら1段階戻る（0未満にはならない。枯れない）。
- `hutStageFor(totalOversleeps)`：おじさんの小屋。0〜2 回：ボロ小屋／3〜9：靴が置かれる／10〜19：小屋が家になる／20〜：豪邸。`ojisanLine` と同じ境界を使う。
- `canPlace(state, itemId, x, y, gridSize)`：範囲内かつ他のアイテムと重ならない。
- `exchange(inventory, wallet, itemDef)`：トークンが足りれば減らして手持ちに加える。コインは一切使えない。

## 3. 画面

### 3.1 ナビゲーション
`go_router` の `StatefulShellRoute` で下タブ3つ。Ringing / Result はシェルの外（全画面）。既存ルートのパスは変えない（テストが依存）。

### 3.2 お庭画面
- 画面上部：帯「🔥 連続起床 12日（最高 20日）」「👨 寝坊 3回」
- 中央：ガラス容器（角丸の縦長カプセル形を `CustomPainter` で描く。上部に光の反射、下部に土の層）。中は **8×6 のグリッド**の地面。配置済みアイテムはグリッド上に描画（プレースホルダー：カテゴリ別の色付き角丸矩形＋絵文字＋名前）
- 住人：おじさん（👨）が地面の空きセルを数秒ごとにゆっくり移動する。タップで現在の成長セリフ（`ojisanLine`）を吹き出しで表示。小屋（`hutStageFor`）は固定位置に常設し、段階に応じて見た目（プレースホルダー：🛖 → 👞 → 🏠 → 🏰）が変わる
- 右下：「模様替え」ボタン → 編集モード
- 左下：「種屋」ボタン → 交換画面

### 3.3 編集モード
- 下部に手持ちアイテムの横スクロール棚。棚からグリッドへドラッグで配置、配置済みはドラッグで移動、棚へドラッグで回収
- 置けないセルは赤く表示。「完了」で保存。「元に戻す」は不要
- 編集モード中も住人は動くが当たり判定には関与しない

### 3.4 種屋
- カタログ一覧（名前・カテゴリ・価格）と「交換」ボタン。トークン不足なら無効
- 上部に現在のトークン残高。**コインは表示しない**。交換以外の入手（配布・イベント）は今後の差し替え用にコメントで注記するだけ

### 3.5 初期状態
- 初回起動時に無料で配布：苔1・小石2・小さな植物1（植物はすぐ配置できるように地面中央に配置済み）
- 小屋は常設（アイテムではない）

## 4. 永続化
drift に `garden_placements` と `garden_inventory` テーブルを追加（マイグレーション、schemaVersion 更新）。

## 5. テスト
- 純粋ロジック：ストリーク（連続、途切れ、空白日、同日複数セッション）、成長段階と後退、小屋段階の境界、配置可否（範囲外・重なり）、交換（不足・成功・コイン不使用）
- ウィジェット：タブ切り替えでお庭が出る／種屋で交換すると棚に増える／編集モードで配置して完了すると再起動後も残る（リポジトリ経由）／既存の Home・Wallet・Settings のテストが壊れていない
- 回帰：UI 上に「広告」「スタミナ」「ルーレット」「課金」「コインで購入」が存在しない

## 6. 実装順序
1. ナビゲーションを下タブ化（既存画面をそのまま載せる）。既存テスト全通過を確認

3. 永続化＋初期配布
4. お庭画面（表示のみ）＋住人の移動＋帯

6. 種屋
7. README 更新（お庭の概要、プレースホルダーの差し替え方針、入手ロジックの差し替えポイント）
