# アラーム機能 v2 仕様 — 編集画面の再設計・スヌーズ・覚悟の罰・寝坊時連絡

`MVP_SPEC.md` / `GARDEN_SPEC.md` の続き。矛盾する場合は本仕様が優先。

## 0. 設計原則の改訂

- **スヌーズは無料の標準機能**として提供する（間隔・上限回数）。**覚悟モードではスヌーズが罰の対象**になる。スヌーズを売り物にすることは引き続き禁止（コインでスヌーズを買う、スヌーズ回数を課金で増やす等は不可）。
- それ以外の原則（無料で全機能、広告は本筋外のみ、課金誘導なし、コインとトークンは相互変換不可）は不変。README の設計原則をこの文言に更新する。
- **罰としての請求は許可**（`docs/BILLING_API.md`）。ユーザーが自分でカードを人質にすると同意した場合に限り、寝坊で確定した金額を月末に合算して請求する。機能を売る課金（スヌーズ・コイン・プレミアム等）は引き続き禁止で、UI の文字列禁止も維持する。
- 通貨表記は「コイン」。

## 1. 編集画面（AlarmEdit）のレイアウト

iOS の設定画面のような「島」形式。各行は左にラベル、右に現在値と `>`（サブ画面へ）またはトグル。

```
[時刻ダイヤル（既存の CupertinoDatePicker。画面全体を再描画しない）]

基本設定
  曜日            月-金 >          サブ画面：曜日チップ。表示は「毎日」「月-金」「土,日」「なし（一回限り）」等に要約
  起床確認        ボタン長押し >   サブ画面：長押し／計算／文字入力／振る／ランダム
  サウンド        bell >           サブ画面：3章
  （起床猶予はここではなく覚悟の設定の行。12章末を参照）
  スヌーズ        [toggle]
  覚悟            [toggle]         新規作成時は OFF

スヌーズ設定（スヌーズ ON のときだけ出現）
  間隔            5分 >            スライダー 1〜30 ＋ 数値入力
  上限回数        3 >              スライダー 0〜10 ＋ 数値入力（0 = 無制限ではなく「スヌーズ不可」。無制限は設けない）

覚悟の設定（覚悟 ON のときだけ出現。赤黒の警告色。上部に「今夜の最大損失 ○○コイン」を大きく表示）
  人質            なし >           サブ画面：なし／コイン／クレジットカード（12章）。既定は「なし」
                                   「なし」なら以下の3行と見出しは出ない（連絡だけの覚悟）
  寝坊時連絡先    田中 太郎 >      サブ画面：5章。未設定なら「なし」
  寝坊ペナルティ  100コイン/分 >   スライダー 10〜上限金額 ＋ 数値入力。覚悟ゲージ（😴〜💀）を併記（10章）
  スヌーズペナルティ 50コイン >    スライダー 0〜上限金額 ＋ 数値入力（スヌーズ OFF なら行を非表示）
  スヌーズ中の加算  [切替]         「規定時刻から加算し続ける」／「次に鳴る時刻を起点にし直す」（スヌーズ OFF なら非表示）
  上限金額        1000コイン >     スライダー 100〜上限金額の最大値（オプションで手入力）
                                   ＋ 数値入力。残高より大きければ警告（保存は可）
                                   上限金額を下げると、寝坊ペナルティ／スヌーズペナルティもその値までクランプされる
```

**スライダー＋数値入力の共通仕様**：スライダーと `TextField` を同期。入力が数値でなければ無視（前の値を保持）、範囲外はクランプ。決定はサブ画面を閉じた時点で反映。

**一覧画面**：行を左にスワイプすると赤い「削除」が現れ、押すと削除（iPhone のアラームと同じ）。削除時はプラットフォームのアラームも取り消す。Undo は不要。

**性能**：ダイヤルの操作で編集画面全体が再描画されないこと（時刻の状態を独立した `StateProvider`／`ValueNotifier` に切り出し、ダイヤル以外は `select` で購読）。

## 2. 起床確認の追加

| 種類 | 内容 |
|---|---|
| shake | 端末を **5秒間振り続ける**。`sensors_plus` の加速度計で、重力を除いた加速度の大きさが閾値（目安 12 m/s²）を超えている状態が続く時間を積算。0.5 秒以上途切れたら 0 に戻す。進捗リングを表示。エミュレータでは振れないので、`ShakeDetector` を純粋ロジック（サンプル列 → 進捗）として切り出して単体テストする |
| random | 鳴動時に長押し／計算／文字入力／振る から抽選。抽選結果はセッションに保存し、再起動後も同じ確認になる |

## 3. サウンド

- **同梱ライブラリ**：5種類以上（bell / buzzer / chime / siren / birds など）。音源はリポジトリ内で合成するか CC0 素材を使い、`assets/audio/LICENSE.md` に出所を明記する。既存の `alarm.wav` は `bell` として残す
- **端末内ファイル**：`file_picker` で音声ファイルを選び、アプリの領域にコピーして使う（元ファイルが消えても鳴るように）。コピー後のパスを保存
- **プレビュー**：サブ画面で各音源の再生／停止。プレビューは通常のメディア音量で、鳴動時はアラーム音量
- YouTube 等のストリーミングは対応しない（README の既知の制約に理由を明記：鳴動の信頼性と利用規約）
- `Alarm.soundId`（ライブラリの id、または `file:<path>`）を追加

## 4. スヌーズと損失の計算（純粋関数・単体テスト必須）

追加モデル：

```
Alarm
  snooze: Snooze?              // null = スヌーズ不可
  soundId: String
Snooze
  intervalMinutes: int         // 1..30
  maxCount: int                // 0..10
Kakugo（追加）
  snoozePenalty: int           // スヌーズ1回ごとのコイン
  snoozeResetsClock: bool      // true = 次に鳴る時刻を起点にし直す
AlarmSession（追加）
  snoozes: List<DateTime>      // 押した時刻
  currentRingAt: DateTime      // 現在の鳴動の起点（初回は firedAt。スヌーズ後は再鳴動時刻）
  wakeCheckResolved: WakeCheckType   // random の抽選結果
```

損失：

```
lossAt(now, session):
  minutePart =
    if snoozeResetsClock:
      billableMinutes(now - currentRingAt, grace) * rate      // スヌーズ中（鳴っていない間）は 0
    else:
      billableMinutes(now - firedAt, grace) * rate            // スヌーズ中も止まらない
  snoozePart = snoozes.length * snoozePenalty
  return clamp(minutePart + snoozePart, 0, min(cap, coinsAtFire))
```

- 「起点にし直す」場合、再鳴動後は猶予も改めて適用する（再鳴動＝新しい鳴動として扱う）
- スヌーズ押下時：`snoozes` に追加、プラットフォームのアラームを `intervalMinutes` 後に再設定、鳴動画面を閉じてホームへ（通知は「スヌーズ中 7:05 に再鳴動」）。`maxCount` に達したらスヌーズボタンを出さない
- スヌーズペナルティは押した瞬間に画面上の損失へ反映される（確定は解除時。ウォレットの減算は従来どおり確定時に一括）
- **成功／失敗**：スヌーズを1回でも使えば failed。使っていなければ従来どおり `elapsed < grace`（起点は firedAt）
- 60分の安全弁は firedAt 基準のまま（スヌーズで延びない）
- 覚悟なしのアラームでもスヌーズは使える（罰なし）。ただしストリーク上は failed
- **`snoozeResetsClock` の既定（改訂5）**：新規アラームは `true`（「次に鳴る時刻を起点に
  し直す」＝一時停止する安全側）を既定にする。スヌーズ中に時間分の損失が黙って積み上がる
  ことを防ぎ、かかるのはスヌーズ罰だけ。`false`（規定時刻から加算し続ける）は任意の opt-in。
  **これは新規作成時の既定だけを変える**：保存済みの行と全デシリアライザのフォールバックは
  `false` のままで、既存アラームは記録された値を保つ（移行しない）。

## 5. 寝坊時連絡（設定・発火・読み上げ。実送信は次フェーズ）

```
OversleepContact
  name: String
  phone: String?
  email: String?
  triggerMinutesAfterGrace: int   // 猶予が切れてから何分で連絡するか。1..60
  message: String?                // メール本文／自動音声の原稿。ユーザー自身の言葉
  recordingPath: String?          // 録音した音声（アプリ領域にコピー）
```

- サブ画面：名前、電話番号、メールアドレス、発火タイミングのスライダー＋数値入力、メッセージ本文（複数行）、録音（`record` パッケージ。録音／停止／再生／削除。マイク権限）
- 連絡先はアラームごとに1件。プリセットとして「最近使った連絡先」を選べる程度で、連絡先アプリとの連携は今回はしない
- **鳴動中**：連絡までの残り時間を画面に表示し、**`flutter_tts` で日本語の合成音声が定期的に読み上げる**（鳴動開始時、残り 3分・1分・30秒、および発火時）。文面例：「あと3分で 田中太郎 さんに連絡が行きます」。TTS はアラーム音の上に重ねる（アラーム音を止めない）
- **発火時**：`OversleepNotifier` インタフェースを通す。今回の実装は `LoggingOversleepNotifier`（発火内容を `contact_events` テーブルに記録し、アプリ内通知「田中太郎 さんへの連絡が送信されました（開発中：実際には送信していません）」を出す）。次フェーズでサーバー送信の実装に差し替える
- 起床確認をクリアした時点で発火予定は取り消す。スヌーズ中は「起点にし直す」設定なら発火タイマーも止め、「加算し続ける」なら止めない
- 発火は1セッションにつき1回

## 6. データ

drift v4：`alarms` に snooze・kakugo の追加列・soundId・contact（JSON 1列でよい）、`sessions` に snoozes（JSON）・currentRingAt・wakeCheckResolved、`contact_events` テーブル。マイグレーションとテスト（v3 の行がそのまま読めること）。

## 7. テスト

- 純粋ロジック：損失（両モード×スヌーズ回数×猶予）、成功判定（スヌーズあり＝失敗）、上限クランプ、ShakeDetector、random の抽選と保存、発火タイミング計算、読み上げタイミング
- ウィジェット：島レイアウトの出現／非出現（トグル連動）、スライダー↔数値入力の同期とクランプ、スワイプ削除、サウンドのプレビュー（プレイヤーはフェイク）、連絡先サブ画面の保存
- 回帰：既存テストを壊さない。UI に「広告」「課金」「スヌーズを購入」等が無いこと（カード人質の画面も同じ規則に従う。使う語は「請求」「カード」「人質」）

## 9. 改訂 2（編集画面レビューを受けての変更）

段階A・Bの実装をユーザーがレビューして出た 9 点。矛盾する場合は本章が上の記述より優先。

1. **スヌーズトグルの副題「無料の標準機能です」を削除。** 無料であることは設計原則が
   保証していて、行に書き足す必要はない。
2. **覚悟トグルの副題は「起床に対するあなたの"覚悟"を設定できます」**（金額の話は中でする）。
3. **「スヌーズ中の加算」は覚悟の設定の行から外し、寝坊ペナルティのサブ画面**
   （スライダー／数値入力の下）へ移す。出現条件は変わらずスヌーズ ON のときだけ。
   その場で下書きに書く（親サブ画面の pop 時 commit と競合させない）。
4. **「起床確認」→「起床確認方法」**（行・サブ画面のタイトル）。
5. **起床確認方法に `normal`（「ノーマル」）を追加。** 解除ボタンを1回押すだけ。
   一覧の**先頭**に置く。**ランダムの抽選対象には入れない**（何もしなくていい選択肢を
   引ける抽選は確認ではない）。DB は名前で読み書きするので列の変更はない。
6. **覚悟の島の見出し「今夜の最大損失」→「寝坊で失う最大金額」**（値の「○○ コイン」はそのまま）。
7. **連絡の送信タイミングは 0〜60 分。** 0 は「猶予が切れたその瞬間」。
8. **アプリ内 連絡帳。** drift v6 で `contact_book_rows`（id / 名前 / よみがな? /
   電話? / メール? / 作成時刻）。モデルは `ContactEntry`。並び順は
   「よみがな、無ければ名前」の Dart 文字列比較でよい。画面は一覧・＋で追加
   （名前必須、電話かメールのどちらか必須、よみがな任意）・タップで選択・
   長押しか右端メニューで編集／削除。**外部キーは張らない**：連絡帳から消えても、
   アラーム側は控え（9 のスナップショット）で動き続ける。
9. **寝坊時の連絡設定を作り直す**（サブ画面の中を3つの島に）。

```
寝坊時の連絡設定  (島)
  連絡先        田中太郎 >     連絡帳を開いて選ぶ。未設定は「なし」
  送信タイミング  猶予後 3分 >  スライダー 0〜60 ＋ 数値入力
  電話          [toggle]      選んだ相手に電話番号が無ければ灰色・押せない
  メール         [toggle]      メールアドレスが無ければ同じく押せない
メール設定 (島、メール ON のときだけ)
  ◯ デフォルト   ◉ カスタムメッセージ  ＋ カスタム時は複数行の入力欄
電話設定 (島、電話 ON のときだけ)
  ◯ 自動音声     ◉ カスタム録音        ＋ カスタム時は既存の録音／停止／再生／削除
```

```
OversleepContact（改訂）
  contactId: String?            // 連絡帳の参照。旧データは null
  name / phone? / email?        // 連絡帳エントリの**控え**
  phoneEnabled / emailEnabled: bool
  mailMode: default|custom      // + mailMessage: String?
  phoneMode: auto|custom        // + recordingPath: String?
  triggerMinutesAfterGrace: int // 0..60
```

- デフォルト文面・自動音声の原稿は固定文（メールは「【Wake or Pay】{あなたの名前} さんは
  HH:MM のアラームを解除できていません。寝坊しています。」、自動音声は同じ文から件名タグを
  除いたもの）。**主語は連絡先ではなく `Settings.userName`（アプリの利用者＝寝坊した人）**で、
  未設定なら「Wake or Pay の利用者」。名前と時刻は**発火時に**埋める。
- 保存形式は JSON 1列のまま。**旧形式を素直に読む**：旧 `message` →
  カスタムメッセージ、旧 `recordingPath` → カスタム録音、住所のある経路は ON。
- `LoggingOversleepNotifier` の記録には**どの経路をどのモードで**「送った」かを残す。

## 10. 改訂 3（録音 UI・覚悟ゲージ・一覧の行）

段階C のレビューで出た 6 点。矛盾する場合は本章が上の記述より優先。

1. **録音のシークバーは、録音が無く録音中でもないときは出さない。** 待機中の
   電話設定は「🎤 録音開始」だけ。
2. **バーの目盛りは状態で変わる。** 録音中だけ上限 30 秒ぶん（ノブが右端＝自動停止）。
   録音後は**その録音の長さ**が横幅いっぱいで、波形は全幅に広がり、再生が終わった
   ところでノブがちょうど右端に着く。
3. **覚悟バッジ／覚悟ゲージは `上限金額 ÷ 寝坊ペナルティ`（＝上限に届くまでの分数）で決める。**
   レートの絶対値では強さが決まらないため。帯は 2分以下 / 5分以下 / 10分以下 /
   30分以下 / それ以上 の 5 段。一覧のバッジは `kakugoBadge(rate, cap)`、編集画面の
   ゲージは `kakugoMood(rate, cap)`。**同じ純粋関数の同じ帯**を読む。

   | 上限までの分数 | バッジ | ゲージ |
   |---|---|---|
   | ≤2分 | 💀 | 💀 寝るな |
   | ≤5分 | 🔥 | 😠 絶対に起きろ |
   | ≤10分 | ⚠️ | 😐 絶対起きる |
   | ≤30分 | 💦 | 🙂 起きなきゃ |
   | それ以上 | 💸 | 😴 まあ起きたい |
   | ペナルティ 0 | （なし） | 😌 ペナルティなし |

4. **「連絡だけの覚悟」は人質「なし」で表現する**（12章）。寝坊ペナルティは
   **10〜上限金額**で、0 は選べない。
   - 人質「なし」なら損失は常に 0（分ごともスヌーズも）。判定と連絡・共有は従来どおり。
   - 一覧にはバッジもペナルティ表記も出さない。
   - **鳴動画面と通知は「1分ごとに 0 コイン」を出さない**（覚悟なしと同じ文面にする）。
   - 編集画面の「寝坊で失う最大金額」は**上限金額のまま**（スヌーズペナルティで到達しうる）。
     人質「なし」なら見出しごと出さない。
   - 覚悟ゲージの「😌 ペナルティなし」帯は人質「なし」のための表示として残す。
   - **旧データ互換**：`ratePerMinute < 10` で保存された行は読み出し時に人質「なし」
     として扱う（10 に丸めて燃やし始めない）。人質名が無い旧行は「コイン」。
5. **一覧の行は覚悟の有無で形を変えない**（README「アラーム一覧の行」を参照）。

## 11. 改訂 4（実送信フェーズ 1：Discord／メール／SMS／電話発信、プロフィールタブ）

> **⚠️ 電話発信の経路は後日廃止した。** バックグラウンド／ロック画面からの
> 自動発信は OEM ごとに挙動がばらばらで信頼できず、Google Play の制約対象で、
> 発信できたかの検証もできない。**SMS・メール・Discord は残す。** 番号は SMS 用に
> 保持し、旧データの `phoneEnabled` は読み捨てる（`fromJson` は投げずに無視）。
> 本章のうち「電話」「`CALL_PHONE`」「`READ_PHONE_STATE`」「`ACTION_CALL`」
> 「スピーカーフォン」「通話中のアラーム停止」に関わる記述はすべて過去の設計であり、

## 12. 人質（覚悟の設定の先頭行）

寝坊で何を失うかの選択。既定は「なし」。

| 人質 | 説明文 | 単位 | 寝坊したとき |
|---|---|---|---|
| なし | 寝坊してもコインもカードも失いません。連絡・共有だけの覚悟です。 | −（金額の行は出ない） | 何も失わない。判定と連絡・共有は従来どおり |
| コイン | 寝坊すると、アプリ内のコインが燃えます。 | コイン | 確定額をウォレットから引く（従来の挙動） |
| クレジットカード | 寝坊で確定した金額を、毎月末にまとめてカードに請求します。 | 円（3桁区切り） | コインは減らさず、端末内の請求台帳 `pending_charges` に1件記録する |

- **1 コイン = 1 円**。保存される数値は同じで、単位の読み方だけが人質で変わる。
- カード未登録なら「クレジットカード」は選べず、下に「カードを登録する」が出る
  （プロフィール › クレジットカード へ）。
- 登録済みカードを解除しても**保存済みアラームは書き換えない**。編集画面の行は
  右側の「クレジットカード」をエラー色にし、補足に「カードが未登録です（プロフィールで登録できます）」を出し、鳴動の確定時はコインに退避する。
- 請求は Phase 3（`docs/BILLING_API.md`）。現時点でネットワークには一切出さない。

**起床猶予は覚悟の設定の行**（寝坊時連絡・共有 の直後、サブ画面はスライダー1〜5＋数値入力）。
寝坊ペナルティのサブ画面内にあった起床猶予セクションは撤去した — 同じ数値を二か所から
編集できる状態は作らない。**人質も連絡・共有も無いアラームでは非表示**：猶予は
「燃え始め」と「寝坊判定→連絡・共有」の起点で、どちらも無ければ何も決めないため。
「寝坊時連絡・共有」サブ画面：

### 11.5 実送信の仕組み（端末内で完結）
| 経路 | 実装 |
|---|---|
| 電話 | `CALL_PHONE` 権限で `ACTION_CALL` により本人の番号から発信。発信直後にスピーカーフォン ON（`AudioManager`。Android のバージョンによって制御できない場合はベストエフォート）。鳴動画面は前面のまま。アラーム音は通話中は一時的に止め、通話終了で再開（止められない場合はそのまま）。 |
| SMS | `SEND_SMS` 権限で本人の番号から送信（`telephony` 系パッケージか platform channel）。Google Play では許可されにくい旨を README に明記。 |
| メール | プロフィールの「メール送信設定」（SMTP ホスト・ポート・ユーザー・**アプリパスワード**・送信元アドレス。Gmail のプリセットあり）を使い、`mailer` パッケージで端末から直接送信。パスワードは `flutter_secure_storage` に保存し、画面には伏せ字。「テスト送信」ボタンで自分宛に送って確認できる。 |
| Discord | Webhook URL に `multipart/form-data` で POST。本文＋共有音声（m4a）を添付。 |
- 送信は `OversleepNotifier` の実装を経路ごとに用意し、`LoggingOversleepNotifier` は「各経路の成功／失敗」をログとして残す（従来の「送信していません」文言は廃止）。
- 送信に必要な権限（電話・SMS・マイク）は、その経路を ON にした時点で要求する。

### 11.7 アプリが止まっていても発火する
- 発火時刻（猶予終了＋送信タイミング。起点は加算モードに従う）に **`android_alarm_manager_plus` で Dart のバックグラウンドコールバック**を予約し、鳴動画面が生きていなくても送信する。解除・スヌーズ（起点リセット時）で取り消し／再予約。鳴動画面側の発火と二重にならないよう、`contact_event_rows` に「このセッションは発火済み」を先に書いてから送る（冪等）。
- 権限：`SCHEDULE_EXACT_ALARM` は既存。

### 11.8 テスト
- 送信器はすべてインタフェース越し（HTTP クライアント・SMTP・電話・SMS はフェイク）。Discord の multipart 本文の組み立て、メール本文、SMS 本文、電話番号の整形を純粋関数で単体テスト。
- 画面：プロフィールタブ、覚悟の設定の新構成、連絡設定のトグル有効条件（相手の番号／アドレス、メール送信設定の有無）、Discord 共有先の追加／トグル、旧 JSON（phoneMode/recordingPath あり）の読み込み。
- 発火の冪等性（鳴動画面とバックグラウンドの両方から呼ばれても 1 回）。

### 11.9 実装順序
**段階C**：上部ヘッダーとプロフィール画面（名前の移動・Discord ID・経験値とレベル・コレクション・アクティビティ枠）→ 覚悟の設定の再構成と 11.3/11.4/11.6 の画面（送信はまだログ）→ Discord Webhook の実送信 → README・APK

## 12. 改訂 5（スヌーズ中の早期解除・スヌーズボタンの視認性）

### 12.1 スヌーズ中でも「起きた」で解除できる
スヌーズ中（`isSnoozePending`＝再鳴動待ちで音は鳴っていない）に、ユーザーが起きたら、再鳴動を待たずに解除できるようにする。起床確認のチャレンジ（長押し・計算等）は課さない——スヌーズは既に一度アラームを止めた操作で、ここでの解除は「起きたことの確認」だけでよい。

- **通知経由**：スヌーズを押した時点で、情報通知に加えて**操作できる通知**を出す。高優先度・展開（BigText）で、本文「スヌーズ中（7:05 に再鳴動）。起きたら『解除』を押してください。」＋アクションボタン**「解除」**。この通知はスヌーズ中ずっと残す（ongoing）。端末のロックを解除した際にできるだけヘッドアップで再掲する（`ACTION_USER_PRESENT` を受けて再ポスト。機種依存のためベストエフォート。通知自体が常に通知領域にある状態は保証する）。
- **通知の「解除」**：タップで WoP を前面に起こし、鳴動画面での解除と同じ確定処理（`SessionService.dismiss`＝現行ルールで failed、損失は解除時点で確定）を行い、**再鳴動アラームをキャンセル**、スヌーズ通知を消し、**リザルト画面**を表示する。
- **一覧経由**：通知を無視した場合、ホームのスヌーズ中の行に**「起きた（解除）」ボタン**を出す。押すと同じ確定処理→リザルト。
- どちらの経路も冪等（既に確定済みなら二度課金しない。既存の settle ガードを使う）。バックグラウンド発火の連絡タイマーも、解除時にキャンセルする。
- 損失の考え方は不変：継続モードは解除時刻まで、起点リセットモードはスヌーズ中の分課金は0＋スヌーズ回数×罰。早期解除は損失を増やさない。

### 12.2 スヌーズボタンの視認性
鳴動画面のスヌーズボタンが文字だけで背景と同化して見えにくい。**枠（アウトライン）または淡い塗り**を与えて押せると分かる見た目にする。ただし主操作である「解除」より視覚的に一段控えめに保つ（スヌーズを主役にしない）。覚悟時の価格表示「スヌーズ（−50 コイン）」はそのまま。

## 13. オプション（アプリ全体の設定）

ヘッダー右端の ⚙ ボタン（`appHeaderOptions`、tooltip「オプション」）で開く。プロフィールと
**同じトップシート**（`TopSheetOverlay`：上から降りてくる非不透明ルート、グラブバー、下フリック
で閉じる、リストの外に固定された「閉じる」）。プロフィールが「あなた」の設定なのに対し、
こちらは「アプリ」の設定。

```
オプション
アプリ
  アプリの更新      1.0.0 (build 10) >  （プロフィールから移設。タップで強制チェック＋ダイアログ）
危険な設定（見出しは colorScheme.error）
  上限金額の最大値  10,000 コイン >     覚悟の設定で選べる上限金額の天井
```

- **上限金額の最大値**：サブ画面の**手入力（内部で 1〜1,000,000 にクランプ。範囲は画面に出さない）**。
  数値 `TextField`（`capCeilingInput`、数字のみ）＋「決定」（`capCeilingSave`）。空・非数値なら
  決定は無効。範囲外はエラーにせず黙ってクランプし、保存後にその値をフィールドへ書き戻す。
  **上げるときだけ**確認ダイアログ（`capCeilingConfirm`：「本当に上げますか？」／
  「やめる」「上げる」）を出す。下げるのは無確認。金額の候補リストは出さない（＝売り物に見せない）。
- 保存先は `shared_preferences` の `options.capCeiling`（`OptionsRepository` →
  `optionsProvider` / `capCeilingProvider`）。既定は 10,000（＝`maxKakugoCap`）。読み出しは
  `normalizeCapCeiling` を通す（未設定のときだけ既定値）。
- **保存済みアラームは天井を下げても勝手に下がらない**。編集画面の上限は
  `effectiveCapCeiling(設定, そのアラームの上限金額)`＝`max(normalizeCapCeiling(設定),
  minKakugoCap, そのアラームの上限金額)`（設定に 1 を入れてもスライダーの max < min にならない）。
  保存値そのもののクランプは `normalizeKakugoCap` が **`absoluteMaxKakugoCap`＝1,000,000** に
  対して行い、ユーザー設定に対しては行わない（`maxKakugoRate` / `maxSnoozePenalty` も
  1,000,000）。
- 文言に課金／購入／広告は出さない。ここで上がるのは**罰の上限**であって、売り物ではない。
