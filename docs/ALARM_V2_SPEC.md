# アラーム機能 v2 仕様 — 編集画面の再設計・スヌーズ・覚悟の罰・寝坊時連絡

`MVP_SPEC.md` / `GARDEN_SPEC.md` の続き。矛盾する場合は本仕様が優先。

## 0. 設計原則の改訂

- **スヌーズは無料の標準機能**として提供する（間隔・上限回数）。**覚悟モードではスヌーズが罰の対象**になる。スヌーズを売り物にすることは引き続き禁止（コインでスヌーズを買う、スヌーズ回数を課金で増やす等は不可）。
- それ以外の原則（無料で全機能、広告は本筋外のみ、課金誘導なし、コインとトークンは相互変換不可）は不変。README の設計原則をこの文言に更新する。
- 通貨表記は「コイン」。

## 1. 編集画面（AlarmEdit）のレイアウト

iOS の設定画面のような「島」形式。各行は左にラベル、右に現在値と `>`（サブ画面へ）またはトグル。

```
[時刻ダイヤル（既存の CupertinoDatePicker。画面全体を再描画しない）]

基本設定
  曜日            月-金 >          サブ画面：曜日チップ。表示は「毎日」「月-金」「土,日」「なし（一回限り）」等に要約
  起床確認        ボタン長押し >   サブ画面：長押し／計算／文字入力／振る／ランダム
  サウンド        bell >           サブ画面：3章
  起床猶予        1分 >            サブ画面：スライダー(1〜5) ＋ 数値入力
  スヌーズ        [toggle]
  覚悟            [toggle]         新規作成時は OFF

スヌーズ設定（スヌーズ ON のときだけ出現）
  間隔            5分 >            スライダー 1〜30 ＋ 数値入力
  上限回数        3 >              スライダー 0〜10 ＋ 数値入力（0 = 無制限ではなく「スヌーズ不可」。無制限は設けない）

覚悟の設定（覚悟 ON のときだけ出現。赤黒の警告色。上部に「今夜の最大損失 ○○コイン」を大きく表示）
  寝坊時連絡先    田中 太郎 >      サブ画面：5章。未設定なら「なし」
  寝坊ペナルティ  100コイン/分 >   スライダー 1〜1000 ＋ 数値入力。覚悟ゲージ（😴〜💀）を併記
  スヌーズペナルティ 50コイン >    スライダー 0〜1000 ＋ 数値入力（スヌーズ OFF なら行を非表示）
  スヌーズ中の加算  [切替]         「規定時刻から加算し続ける」／「次に鳴る時刻を起点にし直す」（スヌーズ OFF なら非表示）
  上限金額        1000コイン >     スライダー 100〜10000 ＋ 数値入力。残高より大きければ警告（保存は可）
```

**スライダー＋数値入力の共通仕様**：スライダーと `TextField` を同期。入力が数値でなければ無視（前の値を保持）、範囲外はクランプ。決定はサブ画面を閉じた時点で反映。

**一覧画面**：行を左にスワイプすると赤い「削除」が現れ、押すと削除（iPhone のアラームと同じ）。削除時はプラットフォームのアラームも取り消す。Undo は不要。

**性能**：ダイヤルの操作で編集画面全体が再描画されないこと（時刻の状態を独立した `StateProvider`／`ValueNotifier` に切り出し、ダイヤル以外は `select` で購読）。

## 2. 起床確認の追加

| 種類 | 内容 |
|---|---|
| shake | 端末を **5秒間振り続ける**。`sensors_plus` の加速度計で、重力を除いた加速度の大きさが閾値（目安 12 m/s²）を超えている状態が続く時間を積算。0.5 秒以上途切れたら 0 に戻す。進捗リングを表示。エミュレータでは振れないので、`ShakeDetector` を純粋ロジック（サンプル列 → 進捗）として切り出して単体テストする |
| random | 鳴動時に長押し／計算／文字入力／振る から抽選。抽選結果はセッションに保存し、再起動後も同じ確認になる |

## 3. サウンド

- **同梱ライブラリ**：5種類以上（bell / buzzer / chime / siren / birds など）。音源はリポジトリ内で合成するか CC0 素材を使い、`assets/audio/LICENSE.md` に出所を明記する。既存の `alarm.wav` は `bell` として残す
- **端末内ファイル**：`file_picker` で音声ファイルを選び、アプリの領域にコピーして使う（元ファイルが消えても鳴るように）。コピー後のパスを保存
- **プレビュー**：サブ画面で各音源の再生／停止。プレビューは通常のメディア音量で、鳴動時はアラーム音量
- YouTube 等のストリーミングは対応しない（README の既知の制約に理由を明記：鳴動の信頼性と利用規約）
- `Alarm.soundId`（ライブラリの id、または `file:<path>`）を追加

## 4. スヌーズと損失の計算（純粋関数・単体テスト必須）

追加モデル：

```
Alarm
  snooze: Snooze?              // null = スヌーズ不可
  soundId: String
Snooze
  intervalMinutes: int         // 1..30
  maxCount: int                // 0..10
Kakugo（追加）
  snoozePenalty: int           // スヌーズ1回ごとのコイン
  snoozeResetsClock: bool      // true = 次に鳴る時刻を起点にし直す
AlarmSession（追加）
  snoozes: List<DateTime>      // 押した時刻
  currentRingAt: DateTime      // 現在の鳴動の起点（初回は firedAt。スヌーズ後は再鳴動時刻）
  wakeCheckResolved: WakeCheckType   // random の抽選結果
```

損失：

```
lossAt(now, session):
  minutePart =
    if snoozeResetsClock:
      billableMinutes(now - currentRingAt, grace) * rate      // スヌーズ中（鳴っていない間）は 0
    else:
      billableMinutes(now - firedAt, grace) * rate            // スヌーズ中も止まらない
  snoozePart = snoozes.length * snoozePenalty
  return clamp(minutePart + snoozePart, 0, min(cap, coinsAtFire))
```

- 「起点にし直す」場合、再鳴動後は猶予も改めて適用する（再鳴動＝新しい鳴動として扱う）
- スヌーズ押下時：`snoozes` に追加、プラットフォームのアラームを `intervalMinutes` 後に再設定、鳴動画面を閉じてホームへ（通知は「スヌーズ中 7:05 に再鳴動」）。`maxCount` に達したらスヌーズボタンを出さない
- スヌーズペナルティは押した瞬間に画面上の損失へ反映される（確定は解除時。ウォレットの減算は従来どおり確定時に一括）
- **成功／失敗**：スヌーズを1回でも使えば failed。使っていなければ従来どおり `elapsed < grace`（起点は firedAt）
- 60分の安全弁は firedAt 基準のまま（スヌーズで延びない）
- 覚悟なしのアラームでもスヌーズは使える（罰なし）。ただしストリーク上は failed

## 5. 寝坊時連絡（設定・発火・読み上げ。実送信は次フェーズ）

```
OversleepContact
  name: String
  phone: String?
  email: String?
  triggerMinutesAfterGrace: int   // 猶予が切れてから何分で連絡するか。1..60
  message: String?                // メール本文／自動音声の原稿。ユーザー自身の言葉
  recordingPath: String?          // 録音した音声（アプリ領域にコピー）
```

- サブ画面：名前、電話番号、メールアドレス、発火タイミングのスライダー＋数値入力、メッセージ本文（複数行）、録音（`record` パッケージ。録音／停止／再生／削除。マイク権限）
- 連絡先はアラームごとに1件。プリセットとして「最近使った連絡先」を選べる程度で、連絡先アプリとの連携は今回はしない
- **鳴動中**：連絡までの残り時間を画面に表示し、**`flutter_tts` で日本語の合成音声が定期的に読み上げる**（鳴動開始時、残り 3分・1分・30秒、および発火時）。文面例：「あと3分で 田中太郎 さんに連絡が行きます」。TTS はアラーム音の上に重ねる（アラーム音を止めない）
- **発火時**：`OversleepNotifier` インタフェースを通す。今回の実装は `LoggingOversleepNotifier`（発火内容を `contact_events` テーブルに記録し、アプリ内通知「田中太郎 さんへの連絡が送信されました（開発中：実際には送信していません）」を出す）。次フェーズでサーバー送信の実装に差し替える
- 起床確認をクリアした時点で発火予定は取り消す。スヌーズ中は「起点にし直す」設定なら発火タイマーも止め、「加算し続ける」なら止めない
- 発火は1セッションにつき1回

## 6. データ

drift v4：`alarms` に snooze・kakugo の追加列・soundId・contact（JSON 1列でよい）、`sessions` に snoozes（JSON）・currentRingAt・wakeCheckResolved、`contact_events` テーブル。マイグレーションとテスト（v3 の行がそのまま読めること）。

## 7. テスト

- 純粋ロジック：損失（両モード×スヌーズ回数×猶予）、成功判定（スヌーズあり＝失敗）、上限クランプ、ShakeDetector、random の抽選と保存、発火タイミング計算、読み上げタイミング
- ウィジェット：島レイアウトの出現／非出現（トグル連動）、スライダー↔数値入力の同期とクランプ、スワイプ削除、サウンドのプレビュー（プレイヤーはフェイク）、連絡先サブ画面の保存
- 回帰：既存テストを壊さない。UI に「広告」「課金」「スヌーズを購入」等が無いこと

## 8. 実装順序（2段階）

**段階A**（編集画面の再設計と周辺）
1. 時刻ダイヤルの再描画分離
2. 島レイアウトへの作り直し（曜日・起床確認・猶予のサブ画面、スライダー＋数値入力の共通部品、覚悟の警告色エリア。スヌーズ・連絡先の行はこの段階では「準備中」ではなく単に未実装で非表示にせず、トグルだけ置いて段階Bで中身を入れる）
3. スワイプ削除
4. 起床確認 shake / random
5. サウンド（ライブラリ・プレビュー・端末内ファイル）
6. README 更新、リリース APK

**段階B**（スヌーズ・罰・連絡）
7. モデル・マイグレーション・損失計算の拡張
8. スヌーズの動作（鳴動画面のボタン、再鳴動、通知）
9. 覚悟の設定の残り（スヌーズペナルティ、加算モード）
10. 寝坊時連絡（設定画面、録音、TTS 読み上げ、LoggingOversleepNotifier）
11. README 更新、リリース APK

## 9. 改訂 2（編集画面レビューを受けての変更）

段階A・Bの実装をユーザーがレビューして出た 9 点。矛盾する場合は本章が上の記述より優先。

1. **スヌーズトグルの副題「無料の標準機能です」を削除。** 無料であることは設計原則が
   保証していて、行に書き足す必要はない。
2. **覚悟トグルの副題は「起床に対するあなたの"覚悟"を設定できます」**（金額の話は中でする）。
3. **「スヌーズ中の加算」は覚悟の設定の行から外し、寝坊ペナルティのサブ画面**
   （スライダー／数値入力の下）へ移す。出現条件は変わらずスヌーズ ON のときだけ。
   その場で下書きに書く（親サブ画面の pop 時 commit と競合させない）。
4. **「起床確認」→「起床確認方法」**（行・サブ画面のタイトル）。
5. **起床確認方法に `normal`（「ノーマル」）を追加。** 解除ボタンを1回押すだけ。
   一覧の**先頭**に置く。**ランダムの抽選対象には入れない**（何もしなくていい選択肢を
   引ける抽選は確認ではない）。DB は名前で読み書きするので列の変更はない。
6. **覚悟の島の見出し「今夜の最大損失」→「寝坊で失う最大金額」**（値の「○○ コイン」はそのまま）。
7. **連絡の送信タイミングは 0〜60 分。** 0 は「猶予が切れたその瞬間」。
8. **アプリ内 連絡帳。** drift v6 で `contact_book_rows`（id / 名前 / よみがな? /
   電話? / メール? / 作成時刻）。モデルは `ContactEntry`。並び順は
   「よみがな、無ければ名前」の Dart 文字列比較でよい。画面は一覧・＋で追加
   （名前必須、電話かメールのどちらか必須、よみがな任意）・タップで選択・
   長押しか右端メニューで編集／削除。**外部キーは張らない**：連絡帳から消えても、
   アラーム側は控え（9 のスナップショット）で動き続ける。
9. **寝坊時の連絡設定を作り直す**（サブ画面の中を3つの島に）。

```
寝坊時の連絡設定  (島)
  連絡先        田中太郎 >     連絡帳を開いて選ぶ。未設定は「なし」
  送信タイミング  猶予後 3分 >  スライダー 0〜60 ＋ 数値入力
  電話          [toggle]      選んだ相手に電話番号が無ければ灰色・押せない
  メール         [toggle]      メールアドレスが無ければ同じく押せない
メール設定 (島、メール ON のときだけ)
  ◯ デフォルト   ◉ カスタムメッセージ  ＋ カスタム時は複数行の入力欄
電話設定 (島、電話 ON のときだけ)
  ◯ 自動音声     ◉ カスタム録音        ＋ カスタム時は既存の録音／停止／再生／削除
```

```
OversleepContact（改訂）
  contactId: String?            // 連絡帳の参照。旧データは null
  name / phone? / email?        // 連絡帳エントリの**控え**
  phoneEnabled / emailEnabled: bool
  mailMode: default|custom      // + mailMessage: String?
  phoneMode: auto|custom        // + recordingPath: String?
  triggerMinutesAfterGrace: int // 0..60
```

- デフォルト文面・自動音声の原稿は固定文（「○○さんは HH:MM のアラームを解除できて
  いません。寝坊しています。」）。名前と時刻は**発火時に**埋める。
- 保存形式は JSON 1列のまま。**旧形式を素直に読む**：旧 `message` →
  カスタムメッセージ、旧 `recordingPath` → カスタム録音、住所のある経路は ON。
- `LoggingOversleepNotifier` の記録には**どの経路をどのモードで**「送った」かを残す。
