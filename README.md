# Wake or Pay — 覚悟の目覚まし

> 「起きなかったら、知らないおじさんが儲かる。」

寝坊した分だけアラームコインが燃え、その額が「おじさん」の収益として表示される目覚まし。
Phase 0（端末内完結・サーバーなし・Android のみ）の実装。

仕様は [`docs/MVP_SPEC.md`](docs/MVP_SPEC.md) が正。お庭は [`docs/GARDEN_SPEC.md`](docs/GARDEN_SPEC.md)。

## 画面構成（下タブ 3 つ）

**アラーム**（既存のホーム、初期表示）／**お庭**／**ウォレット**（履歴と設定への入口）。
鳴動画面とリザルト画面はタブの外の全画面ルートなので、鳴っている間はタブバーが出ない。
模様替え・種屋・設定・アラーム編集も同じく全画面で開く。

### 上部ヘッダー（3タブ共通）

タブ画面はどれも同じヘッダー（`AppHeaderBar`）を被る。左から**アイコン**／**Lv・名前・経験値バー**／
**🎁 ご褒美トークン**／**🪙 アラームコイン**／**＋（ウォレットタブへ）**。

- **鳴動・リザルト・アラーム編集には出さない。** そこは全画面ルートで、ヘッダーを置くと
  「出口があってはいけない画面」に出口を1つ増やしてしまう（鳴っている間タブバーを出さないのと同じ理由）。
- **Home 上部の残高バーは廃止した。** 残高はヘッダーに移り、3タブのどこにいても同じ場所にある。
- **Home の設定アイコンも廃止した。** 設定（テーマ）への入口はウォレットタブの
  「設定・テーマ」の行だけ。
- 名前が長いときに縮むのは**名前プレートのほうだけ**で、残高は縮まない
  （残高が押し出されるヘッダーは、残高バーの代わりにならないので）。
- 名前が未設定のときは `Lv1 未設定` と出る。「＋」はウォレットタブへ移動するだけで、
  その場では何も増えない（チャージは従来どおりウォレットの開発用ボタン）。

### プロフィール（ヘッダーのアイコンをタップ）

**いまの画面の上に**、上からスライドして被さる（`showProfileOverlay`）。不透明ではないので
下のタブは描かれたまま、下タブも動かない。**画面遷移ではなく覆い**なので、下に速くフリックするか
「閉じる」で元の画面にそのまま戻る。中身は3つの島：

| 島 | 内容 |
|---|---|
| プロフィール設定 | **あなたの名前** / **Discord で連携**（状態表示つき。下の「Discord 連携」） / **連携ログ**（直近20件を見る） / **メール送信設定**（設定済み／未設定。下の「メール送信設定」） |
| コレクション | アイコン・名前の背景・フレームを横スクロールで選ぶ。各3種で、**いまは全部所持済み** |
| アクティビティ | 枠だけ。「近日追加：寝坊や起床までの時間をグラフで表示します」 |

- **「あなたの名前」は設定画面から引っ越した。** 設定に残っているのはテーマだけ。
  保存キーは `profile.userName` に変わったが、**読むときは旧キー `settings.userName` に
  フォールバックする**ので、更新してきたインストールで名前が消えることはない。旧キーは
  **読むだけで、書き換えも削除もしない**（古いビルドに戻したときも、名前は元の場所にある）。
- 寝坊時の連絡設定にも「あなたの名前」の行があるが、あれは**入口**で、押すとこのプロフィールが
  開く。名前の置き場所は 1 か所だけにしてある。
- **Discord ユーザーIDは手では入れられない。「Discord で連携」を押した結果としてしか入らない。**
  ID・表示名がその場で入り、行の下が「連携済み：@なまえ」になる。未設定なら、共有投稿は
  メンションではなく名前で呼びかける。「連携を解除」を押すと ID ごと消える。
  詳しくは下の「Discord 連携（OAuth2）」。
- コレクションは所持集合（`Profile.ownedIconIds` ほか）を見て描いているだけで、
  **入手の仕組みはまだ無い**（すべて最初から所持）。所持していないものは薄くなって押せなくなる、
  という経路だけが先に通してある。カタログ（`ProfileCatalog`）は絵文字と色のプレースホルダー。
- プロフィールは drift ではなく **shared_preferences**（`ProfileRepository`）。ヘッダーが
  最初のフレームで描くので、同期的に読めることが要る。

### メール送信設定（プロフィール → メール送信設定）

寝坊のメールは**あなた自身のアカウントから**出る。中継サーバーも代理送信もない代わりに、
SMTP の設定を 1 回だけ自分で入れてもらう。

```
サーバー    プリセット  Gmail / Outlook / iCloud / カスタム
            SMTP ホスト・ポート（プリセットが決めるときは灰色）
            SSL で接続する [toggle]
アカウント  送信元アドレス / ユーザー名 / アプリパスワード（伏せ字）
            [保存]  [テスト送信（自分あて）]
Gmail のアプリパスワードの作り方（画面内に手順）
```

**Gmail のアプリパスワードの作り方**（画面にも同じ手順が出る）：

1. Google アカウントの「セキュリティ」を開く
2. 「**2段階認証プロセス**」を有効にする（**先に有効にしないと次の項目が出てこない**。
   ここで詰まる人がいちばん多い）
3. 同じページの「**アプリパスワード**」を開く
4. 名前を決めて作成すると **16文字**のパスワードが出る
5. その16文字を「アプリパスワード」に貼る（ふだんの Google のパスワードではない）

- **アプリパスワードは `flutter_secure_storage` にしか入らない。** Android の
  keystore に包まれた鍵で AES-GCM 暗号化された、プラグイン専用のファイルに入る。
  アプリの `shared_preferences`（`FlutterSharedPreferences.xml`。ただのプレーンな XML で、
  バックアップにそのまま乗る）には**絶対に書かない**し、ログにも出さない。prefs に入るのは
  `mail.passwordSaved` という **bool 1 個**だけで、これは「保存されているか」しか言わない。
  この不変条件は単体テスト（prefs の全キー・全値をなめてパスワードの断片も無いことを見る）と、
  エミュレータ上の `shared_prefs/` の実ファイル確認の両方で押さえてある。
- **`passwordSaved` は書いたつもりではなく、書けたかどうか。** 保存のあとに secure store を
  読み直して立てるので、keystore が書き込みを拒んだ端末では**未完了のまま**になる。
  7時に初めて気づくより、その場で「まだ未完了です」と言われるほうがよい。
- **保存のとき、パスワード欄が空なら既存のものを触らない。** 伏せ字の欄は保存済みでも空から
  始まる（読み戻せないし、読み戻す理由もない）ので、空 ＝「変更なし」以外に読みようがない。
  消したいときは「削除」ボタン。
- **「テスト送信」は自分の送信元アドレスにだけ送る。** 動作確認のために連絡先へ送りつけない。
  押すと先に保存してから送るので、確かめたのは**実際に保存された設定**になる。
  失敗は理由を出す（`認証に失敗しました` はアプリパスワードの間違い、`通信エラー` は
  ホスト名かネットワーク）。
- **暗号化しない接続は作らない。** `SSL で接続する` が ON なら最初から TLS（465 など）、
  OFF なら STARTTLS（587 など）で、どちらでもない古いサーバーには**送らずに失敗する**
  （`mailer` の `allowInsecure` は常に false）。
- 「設定済み」になるのはホスト・ポート・送信元アドレス・ユーザー名・パスワードが**全部**
  揃ったときだけ。半分入っている状態はアプリ全体で「未設定」として扱う。

### 経験値とレベル

**起床に成功すると経験値が入る。基本 10 ＋ 覚悟のボーナス**で、ボーナスは**ご褒美トークンと
まったく同じ規則**（`kakugoRewardBonus` ＝ 寝坊ペナルティ ÷ 10、上限 50）。同じ規則を 2 か所に
書くとやがて食い違うので、トークンと経験値は 1 つの関数を共有している（`lib/domain/reward.dart`）。

- レベルは累積経験値から毎回導出する。**Lv n に必要な累積 = `25·n·(n−1)`**
  （Lv2=50 / Lv3=150 / Lv4=300 / Lv5=500 …）。保存するのは経験値だけで、レベルは保存しない。
- 経験値は `Wallet` ではなく **`Profile.xp`** にある。**使えない・買えない・何にも変換できない。**
  減ることもない（起床成功でしか動かず、加算しかしない）。コインともトークンとも交換できない。

### アラーム一覧の行（覚悟 ON は別物に見せる）

**覚悟が付いているアラームは、付いていないアラームと同じ顔をしていてはいけない。**
毎朝いくら賭けているのかが、数字を読む前に一目で分かること。
**ただし、変えていいのは色だけで、レイアウトは変えない。**

```
覚悟 ON   06:30 💀                           [ON]    黒地・赤枠・赤いグロー
          毎日
          覚悟あり ・ 500 コイン/分 ・ 📞 ✉ 田中太郎
覚悟なし  08:15                              [ON]    従来どおりの静かな行
          一回限り
          覚悟なし
```

- **行の形は覚悟の有無で変わらない。** 内側のカードも、先頭のバッジ列も置かない。
  時刻の位置・スイッチの位置・右端・行の高さは1ピクセルも動かず、変わるのは
  **背景色・枠とグロー・文字色だけ**（ウィジェットテストで座標を突き合わせている）。
  枠は `foregroundDecoration` で行の上に描く。`border` を内側に持つと中身がずれるため。
- **バッジは時刻のすぐ右**（同じ行）。覚悟ありでペナルティが 1 以上のときだけ出す。
- 3行の内訳：1行目＝時刻（＋バッジ）とスイッチ、2行目＝繰り返し（毎日／平日／一回限り…）、
  3行目＝`覚悟の有無 ・ ペナルティ ・ 連絡先`。ペナルティは 0 のとき、連絡先は
  未設定のとき、それぞれ**丸ごと省く**。
- **起床確認方法と「寝坊で失う最大金額」は一覧から外した**（編集画面には残っている）。
  一覧が答えるのは「いつ鳴るか」「痛いのか」「誰に知られるか」の3つだけ。

- **バッジは「上限まで何分か」＝ `上限金額 ÷ 寝坊ペナルティ` で決める**（`kakugoBadge(rate, cap)`）。
  レートだけでは強さが決まらないため（100 コイン/分でも上限 200 なら 2 分で焼き切れ、
  上限 10000 なら 100 分かかる）。2分以下 💀 / 5分以下 🔥 / 10分以下 ⚠️ / 30分以下 💦 /
  それより長い 💸。**編集画面の覚悟ゲージ（😴〜💀）も同じ関数の同じ帯**を読むので、
  一覧と編集画面が食い違うことはない。**寝坊ペナルティが 0（連絡だけの覚悟）なら
  バッジは出さない。**
- 連絡先が設定されていれば、実際に使う経路の絵文字（📞 電話 / 💬 SMS / ✉ メール）と一緒に
  名前を出す。名前は**連絡帳の現在の値**（`resolveOversleepContact`）。
  共有先があれば、そのうしろに `Discord 2件` が付く（共有だけのアラームは
  `覚悟あり ・ … ・ Discord 2件`）。**経路の絵文字は人にだけ付く**：あれは「その1人にどう届くか」
  を言うもので、部屋の数には対応するものが無い。件数は**行が生きている共有先だけ**を数える。
- スイッチを OFF にしても覚悟の行のまま。枠とグローが弱まるだけで、いくら賭かるかは
  そのまま書いてある（OFF は「今夜は張っていない」であって「覚悟がない」ではない）。
- 色は 3 テーマ共通の固定値（`lib/app/theme.dart` の `kakugoDanger` ほか）。
  テーマで色が変わってよい部分ではないため、編集画面の覚悟の島と同じ定数を使う。
- スワイプ削除とスヌーズ中の表示は両方の行で変わらず動く。

## お庭（起床テラリウム）

起床の積み重ねを眺められる箱庭。ガラス容器の中に 8×6 の地面があり、そこにアイテムを飾る。

- **積み重ねの帯**：`🔥 連続起床 N日（最高 M日）` と `👨 寝坊 K回`
- **連続起床日数**はセッション履歴から純粋関数 `computeStreak` で毎回導出する。**保存しない。**
  その日のセッションが全部 success の日だけ成功日。**アラームを設定しなかった日は途切れない**
  （休日に 0 に戻らない）が、failed が 1 つでもあればその日で途切れる。
- **植物は連続起床で育つ**：0 芽 → 1 若葉（3日）→ 2 つぼみ（7日）→ 3 開花（14日）。
  途切れた日に **1 段階だけ**戻り、0 より下には行かない（枯れない）。判定はその株を**置いた日から**
  の記録だけを畳み込むので、長いストリークの途中に置いた新しい株がいきなり開花することはない。
- **おじさんの小屋は寝坊回数で豪華になる**：`hutStageFor(totalOversleeps)` が
  0〜2 / 3〜9 / 10〜19 / 20〜 で 🛖 → 👞 → 🏠 → 🏰。境界は `ojisanLine` と同一で、
  ずれないことをテストで固定している。
- **住人**：おじさんが空きセルを数秒ごとに歩く。タップで現在のセリフを吹き出しで言う。
  当たり判定には関与しない（模様替え中は `IgnorePointer` で完全に外れる）。
- **模様替え**：棚からドラッグして置く／置いたものをドラッグで動かす／棚へ戻すとしまう。
  置けないセルは赤、置けるセルは緑。**「完了」を押すまで保存されない**（下書きを 1 トランザクションで書く）。
- **種屋**：ご褒美トークンでカタログのアイテムと交換する。**コイン残高は表示しないし使えない。**
- 初回起動時に無料配布：苔1・小石2・小さな植物1（植物は地面の中央に配置済み）。

### プレースホルダーの差し替え方針

いまの見た目はすべて仮で、差し替え先は 3 か所に閉じている。

| いまの実装 | 差し替え先 |
|---|---|
| `lib/features/garden/terrarium_painter.dart` | ガラス容器と土。`CustomPainter` を丸ごと絵に置き換える。レイアウトはここに依存していない |
| `GardenItemTile`（`garden_board.dart`） | アイテム 1 個の見た目（色付き角丸矩形＋絵文字＋名前）。スプライトに置き換える |
| `GardenItemDef.emoji`（`garden_catalog.dart`） | 仮の絵文字。アセット名に置き換える。`id` だけが DB に入るので、名前・価格・見た目は自由に変えてよい |

小屋（🛖👞🏠🏰）と住人（👨）の絵文字も同じく仮。小屋は**アイテムではない**ので地面の 8×6 には
乗らず、地面の上のせりに常設で描いている（配置ルールをアイテムだけの話に保つため）。

### 入手ロジックの差し替えポイント

**アイテムの入手は仮実装。** 種屋でトークンと交換できるだけで、今後ゲーム性のある仕組みに
差し替える前提になっている。差し替え対象は 1 か所だけ：

```
lib/features/garden/item_source.dart   abstract class GardenItemSource
```

`offers()` / `canAcquire()` / `acquire()` の 3 つだけが入手の入口で、棚も地面も種屋も
**在庫を読むだけ**。実装（`SeedShopItemSource`）を差し替えれば入手方法ごと変わる。
差し替えるときも次の 2 つは維持すること：

1. **コインでは何も買えない**（コインは人質であって通貨ではない）。
2. **広告視聴・スタミナ・ルーレット・課金で解放される要素を持ち込まない。**
   `test/features/garden_test.dart` などがこの 5 語（広告・スタミナ・ルーレット・課金・コインで購入）
   が UI に出ないことを回帰テストしている。

## 起床猶予（graceMinutes）

アラームごとに「鳴り始めてから何分までなら起床成功とするか」を 1〜5 分で選べる。既定は 1 分で、
これは従来のルール（60秒未満で解除すれば成功・損失0）とまったく同じ挙動。

- 成功判定：`経過分 < 猶予分`
- 損失：`max(0, 経過分 - 猶予分 + 1) × コイン/分`（そのあと上限と鳴動時残高で頭打ち）
- 猶予 5 分の例：7:04:59 → 成功・0／7:05:00 → 失敗・100／7:06:00 → 失敗・200
- 鳴動画面は猶予が残っている間「猶予 あと 3:42」を表示し、切れると損失カウンタに変わる
- **60 分の安全弁は猶予に関係なく 60 分のまま**

猶予は鳴動開始時にセッションへ固定される（覚悟モードなしのアラームも猶予を持つ）ので、
鳴っている最中にアラームを編集しても、そのセッションの条件は変わらない。

## アラーム編集画面（v2）

`docs/ALARM_V2_SPEC.md` の 1〜3 章、覚悟の設定の中身は 11 章（改訂4）。
iOS の設定画面のような「島」形式。

```
[時刻ダイヤル]
基本設定    曜日 / 起床確認方法 / サウンド / 起床猶予 / スヌーズ[toggle] / 覚悟[toggle]
スヌーズ設定（スヌーズ ON のときだけ）  間隔 / 上限回数
覚悟の設定（覚悟 ON のときだけ・赤黒）  「寝坊で失う最大金額 ○○コイン」
                                     / 寝坊時連絡・共有 / 寝坊ペナルティ
                                     / スヌーズペナルティ（スヌーズ ON のとき） / 上限金額
```

- 覚悟トグルの副題は「起床に対するあなたの"覚悟"を設定できます」。スヌーズトグルには副題を置かない。
- **「スヌーズ中の加算」は行ではない。** 寝坊ペナルティのサブ画面の中（スライダーの下）にある。
  加算モードは「1分ごとにいくら」を**どの分に対して**課すかの話なので、その数字の隣で選ぶ。
  スヌーズ OFF のアラームでは出ない。

- **覚悟は新規作成時 OFF。** 何も賭けていない状態から始まる。
- 各行は右の値と `>` を押すとサブ画面に入る。数値はすべて**スライダー＋数値入力**の共通部品
  （`SliderNumberField`）で、数値でない入力は無視、範囲外はクランプ、**決定はサブ画面を閉じた時点**。
- **時刻ダイヤルは編集画面を再描画しない。** 編集中のアラームは `alarmDraftProvider`
  （開いたアラームをキーにした family）に置き、各行は `select` で自分のフィールドだけを購読している。
  曜日の行だけは Set ではなく**表示ラベル**を購読する（`select` は `==` で比較するので、
  等しい Set 同士は `==` にならず、毎回再描画されてしまうため）。
  `debugAlarmEditBuildCount` を数える `test/features/alarm_edit_rebuild_test.dart` が回帰を防いでいる。
- **一覧のスワイプ削除**：行を左にスワイプすると赤い「削除」が出て、押すと削除。
  `Dismissible` ではない（スワイプだけで消える＝ポケットの中の誤操作で覚悟ごと消える、を避けるため）。
  削除は `AlarmController` 経由なので**プラットフォームのアラームも取り消される**。Undo はない。

### 起床確認方法（6種）

| 種類 | 内容 |
|---|---|
| ノーマル | 解除ボタンを1回押すだけ。**ランダムの抽選には含まれない** |
| 長押し（5秒） | ボタンを5秒間押し続ける |
| 計算（3問） | 2桁の足し算を3問続けて正解する |
| 文字入力 | 表示された文を一字一句そのまま打つ |
| 振る（5秒） | 端末を5秒間振り続ける。重力を除いた加速度が 12 m/s² を超えている時間を積算し、0.5 秒以上途切れたら 0 に戻す |
| ランダム | 鳴動時に長押し／計算／文字入力／振る の4種類から抽選する |

**ノーマルは抽選対象に入れない。** 「何もしなくていい」を引ける抽選は起床確認ではないので、
`randomWakeCheckPool` は 4 種のままにしてある（2000 回引いてノーマルが出ないことをテストで固定）。

`ShakeDetector`（`lib/domain/shake_detector.dart`）は**純粋ロジック**で、サンプル列（時刻＋大きさ）を
入れると進捗が出る。エミュレータは振れないので、ここだけは単体テストが唯一の検証手段になる。
時刻は**センサー側でスタンプする**（`ShakeSample`）。ウィジェットテストで実時計は進められないため、
ウィジェット側で `Stopwatch` を読んでいると注入したサンプルで進捗が動かない。

ランダムの抽選は**鳴動開始時に1回だけ**行い、`AlarmSession.wakeCheckResolved` に保存する。
再起動して鳴動画面に戻っても同じ確認が出る（引き直して簡単なものを狙えない）。

### サウンド

- **同梱ライブラリ 5 種**：ベル（既存の `alarm.wav`）／ブザー／チャイム／サイレン／小鳥。
  すべて `tool/synth_sounds.dart` がリポジトリ内で合成した原著作物で、乱数を使わないため
  再実行してもバイト単位で同一。出所は `assets/audio/LICENSE.md`。
- **端末内のファイル**：`file_picker` で選び、アプリ領域（`getApplicationDocumentsDirectory()/sounds`）に
  **コピーしてから**使う。元ファイルが消えても鳴る。保存する id は `file:<コピー先パス>`。
- **プレビュー**：サブ画面で再生／停止（`audioplayers`、通常のメディア音量）。
  鳴動時はアラーム音量のまま。プレイヤーとファイル選択はどちらもインタフェース
  （`SoundPreviewPlayer` / `SoundFileImporter`）越しなので、テストではフェイクに差し替わる。
- `buildAlarmSettings` は `soundPathFor(alarm.soundId)` を `assetAudioPath` に渡す。
  ライブラリならアセットパス、端末内ファイルなら実パス（`alarm` パッケージはどちらも受け付ける）。
  **どの id にも一致しない場合はベルに落ちる**（無音になるくらいなら違う音で鳴らす）。

### スヌーズ

**無料の標準機能。** 間隔 1〜30 分、上限回数 0〜10。上限回数 0 は「無制限」ではなく
「スヌーズしない」で、無制限は用意しない。覚悟モードのときだけ**罰の対象**になる。

鳴動画面ではスヌーズボタンが**解除より控えめな見た目**（塗りではなくテキストボタン）で
起床確認の下に出る。覚悟モードでは**値段を必ず書く**（「スヌーズ（−50 コイン）」）。
黙って 50 コイン燃やすボタンは、このアプリが絶対に持ってはいけないものなので。

押すと押した時刻が `AlarmSession.snoozes` に積まれ、`currentRingAt` が
`押した時刻 + 間隔` になる。プラットフォームのアラームは**同じ id・同じ payload**で
その時刻に張り直されるので、再鳴動は同じセッションに戻ってくる（新しいセッションは作らない）。
通知は「スヌーズ中 / 7:07 に再鳴動」、ホームの行にも「スヌーズ中 7:07」が出る。

- **起動時の再スケジュールはスヌーズ中のアラームを飛ばす。** `Alarm.set` は同じ id の
  アラームを置き換えるので、素通しすると 7:07 の再鳴動が翌朝に飛ばされてしまう。
- **アプリが死んでも復旧する。** 起動時の復旧はスヌーズ中のセッションを「復帰させるでも
  確定させるでもない第三の結果」として扱い、鳴動画面を出さずに再鳴動だけ張り直す。
- **60 分の安全弁は `firedAt` 基準のまま。** スヌーズで時間は買えない。

#### 覚悟モードでのスヌーズ罰（2つの加算モード）

```
lossAt(now, session):
  起点 = snoozeResetsClock ? currentRingAt : firedAt
  分の部分   = max(0, (now - 起点)の分 - 猶予 + 1) × コイン/分   （負なら 0）
  スヌーズ部分 = スヌーズ回数 × スヌーズペナルティ
  return clamp(分の部分 + スヌーズ部分, 0, min(上限金額, 鳴動時残高))
```

7:00 に鳴り、猶予 1 分・100 コイン/分・スヌーズペナルティ 50・間隔 5 分。
7:02 にスヌーズを 1 回押し、再鳴動は 7:07。上限金額と残高は十分大きいものとする。

| 時刻 | 規定時刻から加算し続ける | 次に鳴る時刻を起点にし直す |
|---|---|---|
| 7:02（押す直前） | 200 + 0 = **200** | 200 + 0 = **200** |
| 7:02（押した瞬間） | 200 + 50 = **250** | 0 + 50 = **50**（起点が 7:07 に移る） |
| 7:05（鳴っていない） | 500 + 50 = **550** | 0 + 50 = **50** |
| 7:07（再鳴動） | 700 + 50 = **750** | 0 + 50 = **50**（猶予がやり直し） |
| 7:08 | 800 + 50 = **850** | 100 + 50 = **150** |
| 7:10 | 1000 + 50 = **1050** | 300 + 50 = **350** |

- 「加算し続ける」ではスヌーズペナルティが**押した瞬間に画面の損失へ上乗せ**される。
  「起点にし直す」では**分の部分がいったん 0 に落ちる**ので、押した直後は逆に安くなる
  （そのぶん、鳴っていない時間は一切課金されない）。ウォレットの減算は従来どおり解除時。
- 「起点にし直す」では**猶予も再鳴動から数え直す**（再鳴動＝新しい鳴動）。
- 合計は上限金額と鳴動時残高でクランプされる。**「今夜の最大損失」は上限金額のまま**で、
  スヌーズ罰を足しても増えない（クランプの中に入っているため）。
- **スヌーズを1回でも押した朝は failed。** どれだけ速く解除しても、いくらも損しなくても、
  覚悟なしのアラームでも同じ。ただし覚悟なしの失敗はおじさんの寝坊回数には数えない（従来どおり）。

### 連絡帳（アプリ内・端末の連絡先は読まない）

寝坊時の連絡先はここから選ぶ。**端末の連絡先アプリには一切アクセスしない**（権限も要求しない）。

- 1件は 名前・**よみがな（任意）**・電話番号?・メールアドレス? ＋ 作成時刻。
  名前は必須、**電話番号かメールアドレスのどちらか**も必須（どちらも無い相手には連絡できないので）。
- 並び順は「よみがな、無ければ名前」を **Dart の文字列比較**（UTF-16 コードユニット順）で
  並べているだけで、日本語の照合順序（辞書順）ではない。かなは encode 順＝あいうえお順に
  並ぶが、**よみがな無しの漢字はコードポイント順**になる。よみがな欄はそのためにある。
- 一覧をタップすると、その人がアラームに**コピー**される。長押しか右端のメニューで編集／削除。
- **削除しても、その人を使っているアラームは動き続ける。** アラーム側には名前・電話番号・
  メールアドレスの控え（スナップショット）が入っていて、参照 `contactId` は目印でしかない。
  削除の確認ダイアログにもそう書いてある。
- **編集した内容は、その人を使っているアラームにもすぐ反映される。** 控えは「真実」ではなく
  **フォールバック**：`contactId` で連絡帳を引き、エントリが生きている限り**そちらの**名前・
  電話番号・メールアドレスを使う（`resolveOversleepContact`）。控えを読むのは、エントリが
  削除されたときだけ。編集画面の行・寝坊時連絡先サブ画面・鳴動中のカウントダウンと読み上げ・
  発火時の記録、すべてこの解決を通っている。
- 控え自体も、サブ画面を開いて閉じたときと `AlarmController.save` のたびに書き戻すので、
  保存値が長期間ずれたまま残ることもない。
- 連絡帳側で**電話番号を消した**なら、その人を使っているアラームの「電話」と「SMS」の
  トグルもそこで無効になる（メールはアドレスに対して同じ）。連絡できない経路が ON のまま残ることはない。逆に**追加**しても、経路が勝手に
  ON になることはない（送るかどうかはユーザーが決めることなので）。

### 寝坊時連絡・共有（覚悟の設定の中）

覚悟の設定の見出し（「寝坊で失う最大金額」）のすぐ下、島の最初の行が「寝坊時連絡・共有」。
値は名前ではなく **`設定済み` / `なし`**。
この 1 行の裏に、連絡する相手・Discord の共有先・送信タイミング・2 つの文面が全部入っているので、
相手の名前だけを出すと、共有だけ設定したアラームが「なし」に見えてしまう。

```
寝坊時連絡・共有  寝坊時連絡先   田中太郎 / なし >
                 寝坊の共有     Discord 2件 / なし >
                 送信タイミング 猶予後 3分 >
```

- **送信タイミングは連絡と共有で共通**（0〜60 分。0 は「猶予が切れたその瞬間」＝`猶予後すぐ`）。
  同じ朝の同じ寝坊について電話と Discord が別々の時刻に出ていけば、2 つの出来事に見える。
  この数字はアラームが 1 つだけ持ち、両方が読む。**v6 まではこの数字が連絡先の JSON の中にあった**
  ので、移行では blob から読み出して `alarm_rows.oversleep_trigger_minutes` に移す（v7 を参照）。
- 共有先の件数は**行が生きているものだけ**を数える。削除された共有先の id は、どこで読んでも
  読み飛ばされる（連絡帳と同じ規則・同じ理由）。
- どのサブ画面も、値は**閉じた時点**で親に返る。3 階層下で編集しても、戻り切ったところで
  下書きに 1 回で載る。

### 寝坊時の連絡設定（個人宛）

1つのアラームに1人。相手は連絡帳から選んで**コピー**される（従来どおり）。

```
寝坊時の連絡設定  あなたの名前（表示だけ。押すとプロフィールが開く）
                 連絡先（連絡帳から選ぶ・未設定は「なし」）
                 電話 [toggle] / メール [toggle] / SMS [toggle] / LINE [toggle・常に無効]
メール・SMS設定（メールか SMS が ON のときだけ）  デフォルト / カスタムメッセージ（＋複数行の入力欄）
```

4つのトグルが灰色になる理由は、それぞれ違う：

| 行 | 押せない条件 |
|---|---|
| 電話 | 選んだ相手に**電話番号が無い** |
| メール | 相手に**メールアドレスが無い**、または**メール送信設定が未完了**。後者なら「メール送信設定を開く」の行が下に出る（説明するより連れて行くほうが早い） |
| SMS | 選んだ相手に**電話番号が無い** |
| LINE | 「まだ実装しない」。モデルにも無く、行があるのは**経路の一覧を欠けさせないため**だけ |

- メールの灰色は**保存された値を OFF に書き換えない。** 以前のバージョンでメールを ON にした
  アラームは持ち主の意思をそのまま持っている。送信側が未完成だからと黙って落とすと、
  設定を入れたときにもう一度押させることになる。
- **権限はトグルを ON にしたその瞬間に要求する**（起動時ではない）。電話は `CALL_PHONE`
  ＋ `READ_PHONE_STATE`、SMS は `SEND_SMS`。**拒否されたらトグルは OFF のまま**で、
  理由が SnackBar に出る。ON のまま保存してしまうと、7時に黙って失敗する経路が
  アラームに入ってしまう——この機能がいちばん避けたい結末そのものになる。
- 連絡帳から人を選ぶと、**番号があれば電話だけが自動で ON** になる（いちばん大きい経路なので。
  ここでも `CALL_PHONE` を要求し、拒否されれば OFF のまま）。
  **SMS は自動では ON にしない**（4時に音を立てないメッセージを送るかどうかは別の判断）。
  メールは「メール送信設定」が済んでいれば自動で ON になる。
- 文面は**メールと SMS で同じ 1 本**。デフォルトは「○○さんは HH:MM のアラームを解除できて
  いません。寝坊しています。」で、**メールだけ先頭に `【Wake or Pay】`** が付く（受信箱で
  見分けるため。件名の無い SMS には付けない）。名前と時刻は**発火時に**埋める（保存された
  文面が古い時刻を抱えることがない）。**文中の名前は寝坊した本人＝プロフィールの名前**であって、
  送られる相手の名前ではない（未設定なら「Wake or Pay の利用者」。画面にも赤字で注意が出る）。

- **電話設定の島（自動音声／カスタム録音）は廃止した。** 改訂4で電話の意味が変わったため：
  **本人の番号から発信して、相手の声で起こしてもらう。音声は流さない。** 流すものが無い以上、
  読ませる原稿も要らない。トグルの副題も
  「相手の電話が鳴ります。スピーカーになり、音声は流れません」になっている。

**電話が実際に何をするか**（`PhoneHandler`）：

- `ACTION_CALL` で発信する。`ACTION_DIAL`（ダイヤラを開くだけ）では、**寝ている本人が
  タップしない限り何も起きない**ので使えない。この違いのために `CALL_PHONE` が要る。
- 発信のあと、**0.5秒おきに最大20回スピーカーを試す**。オーディオモードが `MODE_IN_CALL`
  （または `MODE_IN_COMMUNICATION`）になるまでは、フラグを立てても接続時に戻されるため。
  API 31+ は `setCommunicationDevice(TYPE_BUILTIN_SPEAKER)`、それ以前は
  `setSpeakerphoneOn`。**すべてベストエフォート**で、失敗はログに落として飲み込む
  （耳元で鳴る通話でも、起こせてはいる）。
- 通話の開始・終了は `TelephonyCallback`（API 31+）／`PhoneStateListener` で拾う。
  **`READ_PHONE_STATE` はこれだけに使う**——番号も通話履歴も読まないし、どこにも送らない。
  この権限が無い端末では通話の監視だけが立たず、発信そのものは行われる。
- **通話中はアラーム音を止め、終わったら鳴らし直す。** 相手の声が自分のアラームで
  かき消されては意味がない。`alarm` パッケージに **pause は無い**（API は `set` / `stop` だけ）
  ので、同じ id・同じ payload で `stop` → 1秒後に `set` し直している。鳴り直しは
  `_handled` に残っている id を見つけるので、**新しいセッションは開かず画面も動かない**。
  通話中に起床確認をクリアしていたら鳴らし直さない。
- 鳴動画面には「**田中太郎 に電話をかけました**」の行が出る。連絡ログの行を読んで描いている
  ので、画面と記録が食い違うことはない（失敗していれば「かけられませんでした」）。
- **その島が残した録音ファイルは、次の起動で消える。** `LegacyRecordingCleanup` が起動時に
  1回だけ全アラーム行を舐め、旧 JSON の `recordingPath` が指すファイルを削除し、
  **連絡先の blob を新しい形で書き直す**（書き直すからこそ、2回目の走査は何も見つけず何も書かない）。
  消せないファイルがあっても失敗にはしない。blob からは参照が消えているので、ディスクに
  古いバイトが残るだけになる。

### 寝坊共有設定（グループ宛）

連絡が「ひとりに、起こしに来てもらう」なら、共有は「部屋に、起きられなかったと知らせる」。

```
寝坊共有設定       Discord   2件 / なし >        → Discord 共有先設定
                  X に投稿  [toggle・常に無効]   「まだ実装しない」
共有メッセージ設定  デフォルト / カスタムメッセージ（＋複数行の入力欄）
共有音声の録音     録音 UI（30秒・波形。下記）
```

- デフォルトの共有文面は「HH:MM のアラームを解除できていません。」だけで、**名前を書かない**。
  投稿の 1 行上がすでに誰の話かを言っているので、引用の中で言い直すとアプリが 2 回喋ることになる。
- **共有先が 1 件も選ばれていない共有は保存しない。** 文面と録音だけを持った行き先の無い共有は、
  編集画面の行に「設定済み」と出してしまう。
- 録音があれば投稿に **`share.m4a`** として添付する。録音の途中でこの画面を出ると、その録音は
  **捨てる**（まだ書き終わっていないファイルのパスを保存するほうが悪い）。
- 録音は `record`（AAC/m4a、マイク権限は `permission_handler`、ファイルはアプリ領域）。

#### 録音 UI（シークバー＋波形）

```
録音なし                                バーは出さない。ボタンだけ
[ 🎤 録音開始 ]

[▁▃█▆▂▁                    ]  録音中は 30 秒ぶんの目盛り。ノブ＝経過時間
録音中 6.0秒 / 30.0秒
[ ⏹ 停止 ]                            録音前・録音中は同じ1つの横長ボタン

[▁▃█▆▂▁▃█▆▂▁▃█▆▂▁▃█▆▂▁▃█▆]  録音後はその録音が横幅いっぱい
録音あり 6.0秒 / 再生中 2.5秒 / 6.0秒
[ ▶ 再生 ] [🗑]  ←→  [ ⏹ 停止 ] [🗑]   録音後。🗑 は確認ダイアログを出す
```

- **上限は 30 秒固定**（`maxContactRecordingSeconds`）。設定項目ではない。上限に達したら
  **自分で止まる**（ユーザーが止めてくれるのを当てにしない）。
- **録音が無く、録音中でもないときはバーを出さない。** 動かすものが無いバーは、
  操作できる部品に見えて操作できない。待機中は「🎤 録音開始」だけを出す。
- **目盛りは状態で切り替わる。** 録音中だけ上限 30 秒ぶん（ノブが右端＝上限で自動停止）。
  録音ができたあとは**その録音の長さ**が横幅いっぱいで、波形は全幅に広がり、
  ノブは再生が終わったところでちょうど右端に着く。
- **波形**は `record` の `onAmplitudeChanged`（250ms 間隔＝最大 120 サンプル）で拾った
  dBFS を 0..1 に正規化したもの。`OversleepShare.recordingWaveform` として
  **共有の JSON に一緒に入る**（録音ファイルの隣に別ファイルを置く方式は採らなかった。
  録音の削除・アラームの削除で確実に一緒に消えるほうがよいので）。
  再生済み／録音済みの部分がアクセント色、残りが淡色。
- **波形が取れなくても録音は止めない。** 端末やエミュレータによっては振幅を一切返さない。
  そのときはサンプルが0件になり、バーが平らになるだけ。振幅の購読は録音開始の
  **あと**に行い、await もせず、例外も握りつぶす。
- 録音・再生は `VoiceRecorder` / `VoicePlayer` インタフェース越し（振幅も再生位置も
  インタフェース側にある）なので、ウィジェットテストが**マイクなしで**状態遷移・
  上限での自動停止・削除・波形の描画本数まで全部動かせる。
- 削除だけ確認ダイアログを出す。ここで唯一取り消せない操作だから。
- 保存は **JSON 1列ずつ**：連絡先が `alarm_rows.oversleep_contact`、共有が
  `alarm_rows.oversleep_share`。どちらも丸ごと読み書きするだけで、列の中を検索しない。
- **旧形式もそのまま読める。** `mailMessage` / `mailMode` は `message` / `messageMode` として、
  経路のフラグが無ければ「番号があれば電話 ON・アドレスがあればメール ON・SMS は OFF」として
  読む。`recordingPath` と `phoneMode` は読み捨て（上の起動時の掃除を参照）。

**鳴動中**：「あと 2:30 で 田中太郎 さん と Discord 2件に連絡が行きます」を画面に出し、
`flutter_tts`（ja-JP）で**同じ文を読み上げる**（共有だけなら「Discord 2件に連絡が行きます」）。読み上げは鳴動開始時／残り 3分・1分・30秒／発火時の 5 回、各 1 回だけ。

- **TTS はアラーム音を止めない。** `speak(text, focus: false)` を使う。`focus: true` だと
  プラグインが `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` を要求し、**そのとき小さくなるのは
  こちらが上から喋りたいアラーム音**なので逆効果になる。`focus: false` ならプラグインは
  オーディオフォーカスを一切要求しない。キューは `QUEUE_ADD`（喋りかけを切らない）。
- `AndroidManifest.xml` に `TTS_SERVICE` の `queries` を入れてある。**Android 11 以降は
  これがないと音声エンジンが1つも見えず、無言になる。**
- TTS は `Speaker` インタフェース越し。実装は `SafeSpeaker` で包んであり、**読み上げの失敗が
  鳴動を巻き込むことはない**（黙るだけ）。

**発火**：`OversleepNotifier` インタフェース。今回の実装は `OversleepDispatchNotifier` で、
**電話・SMS・メール・Discord のすべてを本当に送る。**

- まず `contact_events` に**まとめの 1 行**を書く。どの経路をどのモードで送ったかが
  そこに残る（例：`電話 / SMS（デフォルト）：母 さんは 06:05 の… / Discord 2件（カスタムメッセージ）：…＋録音`）。
  **この行は送信より先に書く**：1セッション1回の判定はこの行を見るので、送信の途中で
  再起動しても 2 通目が出てはいけない。書き方は「読んでから書く」ではなく **claim**
  （上の「1セッションにつき1回だけ」）。
- 続けて**経路 1 つにつき 1 行**（`…-phone` / `…-sms` / `…-email`）と、
  **共有先 1 件につき 1 行**（`…-discord-<id>`）を、結果（`成功` / `失敗（認証に失敗しました）` /
  `失敗（HTTP 404）` / `失敗（通信エラー）`）とともに書く。
  まとめて 1 行にすると「2件中1件が失敗」しか残らず、**どの経路・どの部屋に届いたのか**が
  後から読めない。誰も起きていなかった朝の記録を残す意味がそこにしかないので、行は分ける。
- **1つの経路の失敗が隣の経路を止めない。** どの送信器も例外を投げず `SendResult` という値を
  返すので、落ちている SMTP サーバーが SMS も Discord も道連れにすることはない。
- 通知は起きたことをそのまま言う：「Discord 2件に投稿しました」「電話をかけました」
  「SMS・メールを送信しました」「メールは送信できませんでした」。
  **送っていないのに送ったと思わせるのは、機能が無いことより悪い。**
- 記録はウォレットの「寝坊時連絡の記録」に並ぶ（1件も無いうちはセクションごと出ない）。

投稿の中身（`discordOversleepContent`）：

```
<@123456789012345678> が寝坊をしています！      Discord ユーザーID があればメンション
> 07:00 のアラームを解除できていません。          引用記法。カスタム文面ならその文面
[添付：share.m4a]                              共有音声があるときだけ
```

- ID が未設定なら `山田花子 が寝坊をしています！`（名前も未設定なら「Wake or Pay の利用者」）。
  **ping されれば相手の端末が鳴り、名前だけならスクロールで流される**ので、メンションが第一希望。
- 引用は**行ごとに `> ` を付ける**。Discord の引用は行単位なので、先頭に 1 つ置くだけだと
  2 行目以降が引用から外れ、アプリが喋っているように読める。
- 本文は **2000 文字で切る**（Discord は超えた投稿を 400 で拒否し、何も投稿しない＝
  この機能が防ぎたい唯一の結末になる）。切るときはサロゲートペアの途中で切らない。
- 本文は添付の有無にかかわらず **`payload_json`** に載せる。添付ありと無しで 2 種類の
  リクエストを組むと、6時に読むものが 2 つになる。
- **録音ファイルが消えていたら、添付を落として本文だけ投稿する。** 添付できないことは、
  知らせないことの理由にならない。
- 名前・Discord ID・共有先の一覧は**発火の瞬間に読む**。昨夜 ID を入れた／名前を変えたことが、
  それより前に作ったアラームにも効く。行が消えた共有先の id は読み飛ばす。
- 失敗は**例外ではなく値**（`DiscordPostResult`）。すでに寝坊したあとの話なので、失効した
  Webhook 1 件が鳴動画面も損失の時計も**同じ一覧の次の共有先**も巻き込んではいけない。
- 発火タイミングは損失と**同じ時計**に乗っている（`lossClockBase`）。
  「起点にし直す」ならスヌーズで発火も後ろにずれ、「加算し続ける」ならずれない。
- **1セッションにつき1回だけ。** メモリ上のフラグではなく `contact_events` の行で判定する。
  鳴動画面とバックグラウンド isolate は**別プロセスから同じ時刻に**同じセッションへ向かうので、
  「読んでから書く」では両方が「まだ誰も出していない」を読んでしまう。実際には
  `contactSummaryRowId(sessionId)`（**時刻を含まない id**）を 1 トランザクションで
  claim して、取れたほうだけが送る。
- 起床確認をクリアすれば発火予定は消える（鳴動画面が閉じ、発火判定も止まる）。
- HTTP は 1 つの `http.Client`（`httpClientProvider`）越し。テストは必ずフェイクを差し込む
  ——**Webhook URL は誰かの生きた Discord チャンネル**なので、テストから本物の通信に出さない。
  投稿のタイムアウトは 30 秒（30 秒の録音を上りに乗せるため。名前の取得は 5 秒）。

### いま送れるもの／まだ送れないもの

| 経路 | いまの状態 |
|---|---|
| Discord | **実際に投稿する**（本文＋録音の添付、成功／失敗が記録に残る） |
| 電話 | **実際に発信する**（本人の番号から `ACTION_CALL`、スピーカーはベストエフォート、音声は流さない）。**バックグラウンドからは発信できない**（下記） |
| SMS | **実際に送信する**（`SmsManager`。長文は分割して multipart） |
| メール | **実際に送信する**（プロフィールの「メール送信設定」の SMTP アカウントから） |
| LINE / X | 実装しない行が置いてあるだけ |

送信の順は**うるさい順**：電話 → SMS → メール → Discord。枕元で鳴るものが先で、
9時に開く受信箱が後。

### アプリが動いていなくても発火する（仕様 11.7）

鳴動画面は前面にいる間しか送れない。この機能が本当に効いてほしいのは
**アプリをスワイプで消して二度寝した朝**なので、発火時刻を Android の `AlarmManager` にも
`android_alarm_manager_plus` で予約してある。時刻が来ると**専用の Flutter isolate**が立ち上がり、
`oversleepAlarmCallback` が同じディスパッチャを走らせる。

- isolate は UI と何も共有しない（コンテナも、開いている DB も、読み込み済みの prefs も）。
  そこで組み直す。**共有するのは sqlite のファイルだけ**で、それが上の claim を成り立たせている。
- **電話だけはバックグラウンドから出せない。** `ACTION_CALL` には前面の Activity が要る。
  黙って飛ばすとかけたように見えるので、「アプリが起動していないため発信できません」を
  記録に残し、通知にも「電話をかけられませんでした」と出す。
- 予約は鳴動でセッションが開いたときに張り、スヌーズ（起点リセットなら時刻が動く）で張り直し、
  **解除・時間切れ・起動時の復旧で取り消す。**
- 予約 id はセッション id の FNV-1a ハッシュ（`backgroundAlarmId`）。Dart の `String.hashCode`
  は**実行ごとに変わりうる**ので使えない——再起動後に取り消せなくなる。

### Discord 共有先の作り方

Discord 共有先設定の下には**名前の付いたボタンが 1 つ**だけある。＋ も、手動登録も廃止した。

```
[ チャンネルを連携（Discord で選ぶ） ]
```

#### チャンネルを連携（Discord で選ぶ）

1. アラームを開いて **覚悟を ON** →「**寝坊時連絡・共有**」→「**寝坊の共有**」→「**Discord**」
2. 「**チャンネルを連携（Discord で選ぶ）**」を押す
3. **Discord アプリが入っていればそこが開く**（既にログイン済みなら「認証」を押すだけ）。
   無ければブラウザが開き、**投稿先のチャンネルを選ぶ画面**が出る
4. 選んで「認証」を押すと**自動でアプリに戻り**、**共有先が追加され、このアラームで ON になっている**

Discord 側で Webhook を作る作業はまったく無い（Discord が代わりに作ってくれる）。
**この連携の同意画面では、チャンネルの選択に加えて「参加中のサーバーを確認」（`guilds`）
の許可も求められる。** これは連携サーバーが `GET /users/@me/guilds` で Webhook の
`guild_id` を**サーバー名**に変えるためで、**一覧の表示名が既定でサーバー名になるのは
この許可があるからこそ**（許可が無いと 401 で名前が取れず、Webhook 自身の名前に落ちる）。
表示名は**サーバー名**が入る（サーバー名も取れなければ Webhook 自身の名前「Wake or Pay」、
それも無ければ「Discord 連携先」——`webhookDefaultName` の優先順）。**チャンネル名は
ユーザー OAuth では取れない**ので、同じサーバーの 2 チャンネルは同じ表示名で並ぶ。
見分けたいときは**長押し →「名前を変更」**で好きな名前（例：「みんなのサーバー/#報告」）に
できる。押している間は状態表示（下の「Discord 連携（OAuth2）」）が
「Discord を開いています…」→「承認を待っています…」→「連携済み：…」と変わる。

**この経路には連携サーバーの設定が要る**（下の「連携サーバー（重要な変更）」）。
`kDiscordExchangeEndpoint` を空にしてビルドしたものは、ボタンを押したときにそう出る。

- 一覧の**タップはこのアラームの共有先を選ぶ**（アラームごと）。**長押しで テスト送信 /
  名前を変更 / 削除**（共有先そのものの操作で、アプリ全体に効く）。**名前を変更**は表示名だけを
  書き換える（URL は Discord 由来の資格情報なので手では触らせない・空名は拒否）。投稿先そのものを
  付け替えたいときは**削除してもう一度連携**（2 タップ）。
- **テスト送信**が、6時に頼る前に「本当にそのチャンネルに届くか」を確かめる唯一の方法。「Wake or Pay のテスト送信です」の
  1 行だけを、いま投稿する。失敗は理由まで出す（`失敗（HTTP 404）` は消された Webhook、
  `失敗（HTTP 401）` はトークンの作り直し、`失敗（通信エラー）` はトンネルの中）。
- 一覧は**アプリ全体で 1 つ**（サーバーは 1 回登録すれば済む）。アラーム側が持つのは id だけで、
  **外部キーは張っていない**。共有先を消しても、それを選んでいたアラームは
  **そのぶん投稿先が減るだけ**で壊れない（連絡帳と同じ規則・同じ理由）。

## Discord 連携（OAuth2）

Discord には 2 か所つながる。**どちらも同じ認可コードフローで、どちらも連携サーバーを通る。**

| 何をするか | 使う流れ | 連携サーバーが返すもの |
|---|---|---|
| **Discord で連携**（プロフィール）＝ ユーザーID を自動で入れる | 認可コードフロー（`response_type=code`・`scope=identify`） | `{"user":{"id","username","global_name","avatar"}}` |
| **チャンネルを連携**（Discord 共有先設定）＝ 投稿先を Discord に選ばせる | 認可コードフロー（`response_type=code`・`scope=webhook.incoming identify guilds`） | `{"webhook":{…},"guild_name":…}` |

**段階Gで「Discord で連携」も暗黙フローをやめた。** 理由は下の「段階Gで直したこと」の 1 番——
リダイレクト先が https になった以上、暗黙フローの `#access_token=…`（フラグメント）は
**サーバーには届かない**。フラグメントがサーバーに送られないのは仕様であって、それが
暗黙フローの存在理由でもある。結果として良くなった点が 1 つある：
**アクセストークンが端末に一度も来なくなった。** Worker の中で 1 回だけ使われて捨てられ、
アプリが受け取るのは ID・表示名・アバターハッシュだけになる。

どちらの経路も**クライアントシークレット**が要るので、`worker/` が要る。
APK に埋めたシークレットは誰でも取り出せるので、そこだけを外に出している。

### 段階Fで作り直した理由（報告された不具合の正体）

報告された不具合はこう：「Discord で連携」を押してブラウザで承認しても、プロフィールが
「連携済み」にならない。エミュレータで再現し、原因は**2つ**あった。どちらも下の作り直しの
理由になっている。

1. **戻ってきた intent が別のタスクに届いていた。** 旧実装（`flutter_web_auth_2`）の
   `CallbackActivity` は `android:taskAffinity=""` でマニフェストに登録されており、
   ブラウザが投げる `wakeorpay://discord/callback#…` の intent は**アプリ本体とは
   別のタスク**（logcat で `taskId=63`、`isVisible=false`）に届いていた。Dart の future は
   ちゃんと解決していて、アプリは裏側では「連携済み」になっていた。だが**画面はブラウザの
   Custom Tab のまま**で、結果を伝える SnackBar は誰も見ていない画面に出て消えていた。
   ユーザーから見れば「承認したのに何も起きない」（Chrome を手で閉じて元の画面に戻ると、
   消えかけの SnackBar が実際に見えた）。
2. **直したあとに見つかった2つめ。** MainActivity に `wakeorpay` の intent-filter を足した
   瞬間、Flutter エンジンの既定のディープリンク処理が `wakeorpay://discord/callback#access_token=…`
   を **go_router のパスとして**渡してしまい、アプリ全体が赤い
   `Page Not Found / GoException: no routes for location: wakeorpay://…` に差し替わった。
   マニフェストで `flutter_deeplinking_enabled=false` にして解決している
   （コールバックの受信は `app_links` が Intent を直接読むので、これで何も失わない）。

この2つを踏まえて、コールバックの受け取り方そのものを作り直した（下）。SnackBar で結果を
伝えるのもやめた——それが (1) で誰にも見られずに消えた張本人だから。

### 段階Gで直したこと（実機で出た、段階Fでは見えなかった 2 つ）

段階F はエミュレータでは通っていた。実機（Pixel・Discord アプリ導入済み・既定ブラウザ Brave）で
「Discord で連携」を押すと、こうなった。

1. **Discord がカスタムスキームのリダイレクトを受け付けない。** 承認まで進めても、
   Discord は `discord.com/oauth2/error?error=invalid_request` に着地して
   「**Redirect URI 'wakeorpay://discord/callback' is not supported by client**」と出す。
   コールバックは**送られない**ので、アプリは「承認を待っています…」のまま 5 分待って
   時間切れになる。段階F の作り直し（intent がどのタスクに届くか）は正しかったが、
   **そもそも intent が投げられていなかった**。

   → **リダイレクト先を Worker の https URL にした**（下の「App Links とリダイレクト URI」）。
   これに伴い「Discord で連携」も認可コードフローに移った（フラグメントは https では
   サーバーに届かないため）。

2. **`externalNonBrowserApplication` が Discord アプリではなくブラウザに落ちる。**
   これは url_launcher の不具合ではなく、Discord アプリが**登録していない**というだけ。
   実機で `pm query-activities` を読んで確かめた：

   | 投げた URI | 解決先 |
   |---|---|
   | `https://discord.com/channels/@me` | `com.discord/.main.MainActivity` **と** ブラウザ |
   | `https://discord.com/oauth2/authorize` | **ブラウザのみ** |
   | `https://discord.com/api/oauth2/authorize` | **ブラウザのみ** |
   | `discord://-/oauth2/authorize`、`discord://discord.com/oauth2/authorize`、`discord://-/channels/@me`、`discord://app` | **No activities found** |

   `com.discord` は入っていて `discord.com` の App Links も検証済みなのに、
   intent-filter がパスを列挙していて `/oauth2/authorize` を意図的に外している。
   `discord:` スキームに至っては 1 つも登録していない。
   つまり **Android で認可画面を Discord アプリの中に出す方法は無い**。
   `FLAG_ACTIVITY_REQUIRE_NON_BROWSER` は「ブラウザを候補から外す」だけで、
   非ブラウザの受け手を生み出しはしない。

   → **ブラウザ 1 回だけ開く**ようにした（余計な 1 回の失敗を挟まなくなった）。
   代わりに**帰り道**に手をかけた（App Links、下）。連携ログには
   「ブラウザで Discord を開きました（Discord アプリは承認画面に対応していません）」と残す。

### App Links とリダイレクト URI（段階G の中心）

リダイレクト先はこの 1 本になった。**Developer Portal に登録するのもこの文字列ちょうど。**

```
https://wake-or-pay-discord.wakeorpay.workers.dev/discord/callback
```

https にすると「ブラウザに着地したあと、どうやってアプリに戻すか」が新しい問題になる。
3 段構えで解いてある。**上から順に静かに戻る。**

1. **App Links（検証済みなら、ブラウザは 1 ミリ秒も映らない）。**
   `MainActivity` に `android:autoVerify="true"` の intent-filter を足した——
   scheme `https`・host `wake-or-pay-discord.wakeorpay.workers.dev`・path `/discord/callback`
   ちょうど（ホスト全体を掴むと `assetlinks.json` 自身までアプリに来てしまう）。
   Android はインストール時と更新時に
   `https://wake-or-pay-discord.wakeorpay.workers.dev/.well-known/assetlinks.json`
   を取りに行き、そこに載っている SHA-256 が**実際の署名証明書**と一致すれば、
   この URL への遷移をブラウザではなくアプリに直接渡す。Brave も Chrome も Chromium 系は
   OS の検証結果に従うので、承認した瞬間にアプリが前に出る。

   `assetlinks.json` は Worker が配っている（`worker/src/index.ts`）。載せる指紋は
   `wrangler.toml` の `ANDROID_CERT_SHA256`。**いまはデバッグ用キーストアの指紋**で、
   `android/app/build.gradle.kts` がリリースビルドもデバッグ鍵で署名しているから。

   ```
   keytool -list -v -keystore %USERPROFILE%\.android\debug.keystore \
           -alias androiddebugkey -storepass android
   ```

   **リリース用キーストアを用意したら、同じコミットでこの値も差し替えること。**
   ずれると検証が落ちて、下の 2 と 3 に落ちる（動きはするが、ブラウザが一瞬見える）。

   確認方法（端末）：

   ```bash
   adb shell pm verify-app-links --re-verify com.wakeorpay.wake_or_pay
   adb shell pm get-app-links com.wakeorpay.wake_or_pay
   ```

2. **着地ページの「Wake or Pay を開く」ボタン（＝実際に効く道）。** 詳しくは次の
   「段階H」。ブラウザに着地してしまったら、**確実なのはユーザーのタップだけ**なので、
   ページはそのボタンを主役にしてある。`wakeorpay` の intent-filter は段階F から
   **そのまま残してある**——`intent://` が解決した先がこれ。
3. **自動の再挑戦（best effort）。** ページが読み込まれた直後に `intent://` へ、
   1.2 秒後に 2 本目の App Link パス `/discord/callback/return` へ、それぞれ 1 回だけ
   遷移を試みる。通ればユーザーは何も押さずに戻ってくる。通らなくても何も壊れない。

**認可コードはどこにも記録しない。** Worker はログを出さないし、このページは `no-store` で、
コードはページ内の URL の中にしか現れない。ページが持ち越すのは `code` `state` `error`
`error_description` の 4 つだけで、それ以外のパラメータは落とす（値は URL エンコードを
経てから HTML エスケープされるので、引用符もタグも属性の外には出られない）。

### 段階Hで直したこと（Brave/Chrome から本当に戻ってくるようにする）

段階G のあと、実機（Pixel・既定ブラウザ **Brave**）で報告された症状はこう:
**認証したあと着地ページまでは戻ってくるのに、アプリが開かない。ブラウザのまま止まる。**

**Android 側は全部正しかった。** 実機で測ってある:

- `pm get-app-links` は `wake-or-pay-discord.wakeorpay.workers.dev: verified`
- `pm query-activities` はコールバック URL を `MainActivity` に解決する

つまり犯人は OS ではなく、**ブラウザの中の受け渡し**。Chromium にはこの症状を
そのまま説明する規則が 2 つある。

1. **リダイレクトの終着点として着いた App Link は、アプリに渡されない。**
   Chromium がアプリに譲るのは「ユーザーが始めた」と見なせる遷移だけで、
   Discord の認可 → リダイレクト の連鎖はまさにそれに当たらない。
2. **ユーザー操作なしの、未知スキームへのスクリプト遷移はブロックされる。**
   段階G のページがやっていた `location.replace('wakeorpay://…')` は
   ちょうどこの形で、黙って捨てられていた。

だから段階H は、**押せるボタンを主役に据え直した**。

- **主役は大きなボタン 1 個。** `href` は
  `intent://discord/callback?code=…&state=…#Intent;scheme=wakeorpay;package=com.wakeorpay.wake_or_pay;S.browser_fallback_url=…;end`。
  タップはユーザー操作なので Chromium は通すし、`intent://` にパッケージ名まで
  書いてあるのは Chromium がいちばん素直に従う形。文言は「**Wake or Pay を開く**」。
- **ページが「終わった」ように見えないようにした。** 見出しは
  「**認証できました。あと 1 タップです。**」、その下に
  「この画面のままでは連携は終わりません。下のボタンでアプリに戻ってください。」。
  前のページは「Wake or Pay に戻っています…」とだけ書いてあり、ユーザーは
  終わったと思ってブラウザを閉じていた。
- **自動の再挑戦は残すが、best effort と割り切った。** `setTimeout` で `intent://`、
  1.2 秒後に `/discord/callback/return`。**1 フローにつき 1 回だけ**
  （`sessionStorage` に `state` で印を付ける）で、アプリが前に出たあと
  （`document.visibilityState !== 'visible'`）は撃たない。
- **2 本目の App Link パス `/discord/callback/return` を足した。** 上の規則 1 の裏返しで、
  **新しいトップレベル遷移**なら渡してくれる Chromium ビルドがある。マニフェストの
  `autoVerify` フィルタに追加し、`isDiscordCallbackUri` も受け付ける。検証はホスト単位
  なので、パスを足しても検証のやり直しは要らない。
- **`browser_fallback_url` は着地ページ自身ではなく `/discord/callback/return` に向けた。**
  自分自身に戻すと、また自動遷移して、また失敗して、と使い切ったコードを
  アドレスバーに載せたままループする。`/return` は自動遷移を**一切しない**行き止まり。
- 「戻らない場合はこちら」の下には `https のリンクで開く`（＝`/return`）と
  `wakeorpay:// で開く` も残してある。

**ユーザーがやること**：認証のあと戻ってこなかったら、
ブラウザに出ている「**Wake or Pay を開く**」を押す。それだけ。

エミュレータでの確認（`emulator-5554`）:

```bash
adb shell pm verify-app-links --re-verify com.wakeorpay.wake_or_pay
adb shell pm get-app-links com.wakeorpay.wake_or_pay          # → verified
adb shell pm query-activities -a android.intent.action.VIEW \
  -c android.intent.category.BROWSABLE \
  -d 'https://wake-or-pay-discord.wakeorpay.workers.dev/discord/callback/return?code=x&state=y'
# ボタンのタップと同じもの（am は intent: URI を Intent.parseUri で読む）
adb shell am start 'intent://discord/callback?code=…&state=…#Intent;scheme=wakeorpay;package=com.wakeorpay.wake_or_pay;end'
```

`state` は**デバッグビルドだけ** logcat に出る（`wop-discord-state=…`）。
Chrome の URL バーは認可 URL を途中で切ってしまい、末尾の `state` が読めないため。
`state` は CSRF 用のノンスであってクレデンシャルではない（**コードはどこにも出さない**）。

### 新しいフロー

- 認可ページを開くのは **`url_launcher`**、`LaunchMode.externalApplication` **1 回だけ**。
  Discord アプリを狙う試行は段階G で**やめた**（上の 2 番：Discord アプリは
  `/oauth2/authorize` も `discord:` スキームも登録していないので、狙う先が存在しない）。
  開けなければ「ブラウザが見つかりませんでした」と出る。
- 戻り先は **`app_links`**。受けるのは **MainActivity ただ 1 つ**（`launchMode="singleTask"`）で、
  intent-filter は 2 本：https の `autoVerify="true"`（ホスト
  `wake-or-pay-discord.wakeorpay.workers.dev`、パスは `/discord/callback` と
  `/discord/callback/return` の 2 本ちょうど。これが本命）と、`wakeorpay` スキーム
  （着地ページの `intent://` ボタンが解決した先）。
  **どちらが来ても同じ 1 本の解釈器**が読む（`isDiscordCallbackUri` / `parseDiscordCallback`）。
  `flutter_web_auth_2` は依存から**外した**。
- 同時に走らせられるフローは **1 つだけ**。`state` で照合し、**5 分**で時間切れになる。
  「やめる」で自分から打ち切ることもできる。
- 「チャンネルを連携」（サーバー／チャンネル選択）も**まったく同じ経路**を通る。
- コールバックが読むのは**クエリだけ**（`?code=…&state=…` / `?error=…&error_description=…`）。
  フラグメントはもう読まない——暗黙フローが無くなって、フラグメントに入るものが無くなった。
- **状態表示**（プロフィールの Discord 行と、Discord 共有先設定の両方に出る。SnackBar は使わない）：
  「Discord を開いています…」→「承認を待っています…（ブラウザで許可してください）」→
  「連携サーバーに問い合わせています…」→「連携済み：@なまえ」。失敗はそれぞれ固有の文言で出る：
  state 不一致は「確認に失敗しました。アプリからもう一度お試しください」、拒否は
  「Discord で許可されませんでした」、時間切れは「承認が返ってきませんでした。Discord の画面に
  「Redirect URI … is not supported by client」と出ていた場合は、Developer Portal の
  OAuth2 → Redirects に `https://wake-or-pay-discord.wakeorpay.workers.dev/discord/callback`
  を 1 文字違わず登録してください。」、通信失敗は
  「ユーザー情報を取得できませんでした（連携サーバーの応答なし）」。
- **連携ログ**（プロフィール → Discord の島から開くサブ画面）に、直近 20 件を時刻つき・新しい順で
  残す。端末には**保存しない**（メモリのみ）し、**トークンは 1 行も記録しない**
  （トークンが来たことは記録するが、値は記録しない）。

### 端末に残るもの・残らないもの

- **アクセストークンは端末に来ない**（段階G で強くなった点）。両方のフローが認可コードに
  なったので、トークンは Worker の中で 1 回使われて捨てられ、アプリには渡らない。
  `shared_preferences` にも `flutter_secure_storage` にも当然書かない
  （prefs の全キー・全値をなめて、トークンの断片も無いことを見る単体テストで固定してある）。
- 残るのは **ユーザーID・表示名・アバターハッシュ**の 3 つだけ。どれも公開の値で、
  それを持っていてもあなたの代わりに何かができるものではない。**手入力の経路はもう無い**ので、
  この3つは常に「認可された口座から来た」ものだけになる。
- **「連携を解除」は ID も一緒に消す。** ID だけ残すと、解除したはずの口座を
  メンションし続けることになる。
- 連携サーバーは**ユーザーのデータを何も持たない**。DB もセッションもログもない。
  返してくるのは Webhook と、そのサーバー名だけで、**アクセストークンもリフレッシュトークンも
  アプリには渡らない**。

### Discord Developer Portal と連携サーバー（この機能を使う人がやること）

**段階G から、どちらの機能にも 1〜4 の全部が要る**（「Discord で連携」も認可コードフローに
なり、連携サーバーを通るようになったため）。

**1. アプリを作る**

1. https://discord.com/developers/applications を開いて「**New Application**」
2. 名前を決めて作る（この名前が、作られる Webhook の既定の名前になる）

**2. リダイレクト URI を登録する**

3. 左の「**OAuth2**」→「**Redirects**」→「**Add Redirect**」
4. 次を**1 文字違わず**入れて **Save Changes**：

   ```
   https://wake-or-pay-discord.wakeorpay.workers.dev/discord/callback
   ```

   ここが違うと、同意画面が出る前に
   `discord.com/oauth2/error?error=invalid_request` で止まり、アプリは永久に待つ。

   **`wakeorpay://discord/callback` は登録しても意味が無い**（段階F まではこれだった）。
   Discord はカスタムスキームのリダイレクトをこのアプリに許さず、
   「Redirect URI 'wakeorpay://discord/callback' is not supported by client」で断る。
   自分の Worker を建てたなら、ここもその URL に読み替えること
   （`https://<ワーカー名>.<サブドメイン>.workers.dev/discord/callback`）。

5. 同じページの「**Client ID**」を控える。既定では
   `lib/domain/discord_oauth.dart` の `kDiscordClientId` が
   **`1542696296337506415`** になっている。自分のアプリを使うなら、この定数を
   自分の Client ID に書き換えてビルドし直す（Client ID は秘密ではない。
   認可 URL に必ず入る値なので、ソースにあってよい）。

**3. 連携サーバー（Cloudflare Worker）を立てる**

手順の全文は [`worker/README.md`](worker/README.md)。要点だけ：

```bash
npm i -g wrangler
wrangler login
cd worker
wrangler secret put DISCORD_CLIENT_SECRET   # Portal の OAuth2 → Reset Secret で出る文字列
wrangler deploy
```

**シークレットは `wrangler.toml` にもリポジトリにも絶対に書かない。**
`wrangler secret put` で入れたものは Cloudflare 側に暗号化されて置かれる。

**4. 出てきた URL を `kDiscordExchangeEndpoint` に書いてビルドし直す**

`wrangler deploy` の最後に出る
`https://wake-or-pay-discord.<あなたのサブドメイン>.workers.dev` を、
`lib/services/discord_exchange.dart` の `kDiscordExchangeEndpoint` に書いて、
アプリを**ビルドし直す**。詳しくは下の「連携サーバー（重要な変更）」。

### 連携サーバー（重要な変更）

`lib/services/discord_exchange.dart` の `kDiscordExchangeEndpoint` が**唯一の設定箇所**になった。
ランタイムの上書き（prefs の `discord.exchangeEndpoint`）と、プロフィールの「連携サーバーURL」の
行は**廃止した**。理由は2つ：デプロイの詳細（自分がどの Worker を建てたか）をユーザーに
知らせる形になっていたことと、**認可コードの送り先**をアプリの中から誰でも書き換えられる形に
なっていたこと。Worker を建てる人と APK を建てる人は同じ人なので、これはビルドに属する設定であって、
プロフィールに置く値ではない。

**このリポジトリのビルドは以下を指している：**

```dart
const kDiscordExchangeEndpoint =
    'https://wake-or-pay-discord.wakeorpay.workers.dev';
```

ベース URL だけを入れる（`/discord/exchange` はアプリが付ける。末尾のスラッシュも、
フルパスを貼っても通る）。

- **自分のフォークを配るなら、必ず自分の Worker の URL に書き換えてビルドし直すこと。**
  他人の Worker を指したままのビルドは、**その人のクライアントシークレット**を
  自分のユーザーの認可に使うことになる。
- 空にしておくと、段階G からは**どちらの機能も**名指しで断る
  （「連携サーバーが設定されていないビルドです」）。段階F までは「Discord で連携」だけは
  サーバー無しで動いたが、暗黙フローをやめたのでその抜け道は無くなった。
- URL は **https のみ**。本文が認可コードなので、暗号化されていない経路には出さない。
- **変更したら再ビルドが要る。** もう端末に貼る場所は無い。

## プライバシー（端末の中にしか無いもの）

このアプリがネットワークに出るのは **Discord**（投稿・Webhook 名の取得・OAuth2）と、
**あなたが立てた連携サーバー**（「チャンネルを連携」のときだけ）と、
**あなたが自分で入れた SMTP サーバー**だけ。ほかにデータを送る先は無い
（分析・クラッシュ収集・広告の SDK も無い）。SMS と電話は**アプリのサーバーを一切通さず**、
端末の無線から直接出る。

**資格情報は端末から出ない。** SMTP のアプリパスワードは `flutter_secure_storage`
（Android keystore に包まれた鍵で暗号化）にだけ入り、`shared_preferences` にも、ログにも、
どのネットワーク先にも出ない。使うのは、あなたが指定した SMTP サーバーに対して認証する
その一瞬だけ。Webhook URL も同じ扱いで、Discord に対してしか使わない。

| もの | 置き場所 | 外に出るか |
|---|---|---|
| Webhook URL | drift の `discord_webhook_rows`（端末内） | **アプリの外へは送らない。** 投稿するとき Discord に対してだけ使う |
| 連絡帳（名前・よみがな・電話番号・メールアドレス） | drift の `contact_book_rows`（端末内） | 出ない。**端末の連絡先アプリも読まない**（権限も要求しない）。番号とアドレスは**その相手に発信・送信するときだけ**使う |
| アラームが持つ連絡先の控え | `alarm_rows.oversleep_contact`（端末内） | 出ない |
| SMTP のアプリパスワード | **`flutter_secure_storage`**（Android keystore で暗号化。`shared_preferences` には入れない） | **出ない。** あなたが指定した SMTP サーバーへの認証にだけ使う |
| メール送信設定のサーバー項目（ホスト・ポート・送信元アドレス・ユーザー名） | shared_preferences（端末内） | 送信元アドレスとユーザー名は、その SMTP サーバーに対してだけ使う |
| 共有音声の録音 | アプリ領域の m4a ファイル（パスは共有の JSON 列に） | **選んだ Discord 共有先にだけ**、`share.m4a` という名前で添付される |
| プロフィール（名前・Discord ユーザーID・経験値・コレクション） | shared_preferences（端末内） | 名前または Discord ID は**投稿の本文に入る**（それが投稿の目的） |
| Discord の表示名・アバターハッシュ（連携したとき） | shared_preferences（`profile.discordUsername` / `profile.discordAvatar`） | **出ない。**「連携済み：@なまえ」を出すためだけの表示用 |
| Discord のアクセストークン | **どこにも保存しない** | `/users/@me` に 1 回使って捨てる。prefs にも secure store にもメモリ上の永続オブジェクトにも残らない |
| 連携サーバーの URL（Worker） | **ソースコードの定数**（`kDiscordExchangeEndpoint`）。端末には保存しない | ビルドに焼き込まれ、「チャンネルを連携」のときだけそのサーバーに認可コードを送る |
| 連携ログ | **メモリのみ**（直近20件）。端末にも残らない | 出ない。**トークンは1行も入らない**（来たことは記録するが値は記録しない） |
| 寝坊時連絡の記録 | drift の `contact_event_rows`（端末内） | 出ない |

- **Webhook URL は資格情報として扱う。** それを持っている人は誰でもそのチャンネルに投稿できる。
  だから**全文が出るのはアプリ自身の編集フォームだけ**で、共有先の一覧には表示名しか出さない。
  投稿の添付ファイル名も `share.m4a` に付け替える（端末上のパスにはアラームの id と
  アプリの私的ディレクトリが入っているため）。
- 共有先を削除すれば URL も行ごと消える。録音は「削除」を押したときにファイルごと消える
  （下の既知の制約も参照）。

## 設計原則（変更不可）

1. 起こすための機能はすべて無料。枠数・回数・上位機能の制限は一切設けない。
2. 広告なし。課金誘導 UI なし。**スヌーズは無料の標準機能**（間隔と上限回数を自由に設定できる）で、
   **売り物にはしない**。コインでスヌーズを買う、課金でスヌーズ回数を増やす、といった経路は今後も置かない。
   覚悟モードではスヌーズが**罰の対象**になる（1回ごとにコインが燃える）。罰であって商品ではない。
3. コインとご褒美トークンは相互変換不可。UI にも変換経路を置かない。
   **経験値も同じ**で、使えない・買えない・何にも変換できない（起床成功で増えるだけ）。
4. 上限や残高に達しても**アラームは止まらない**。損失表示が止まるだけ。

`test/features/alarms_test.dart` の回帰テストは「広告」「プレミアム」「アップグレード」「課金して」
「スヌーズを購入」「スヌーズを追加」が UI に出ないことを固定している。**「スヌーズ」という語自体は
禁止語ではなくなった**（無料の標準機能になったため）。禁止しているのは売ることだけ。

### なぜ drift を選んだか（hive / isar ではなく）

- **セッション履歴がクエリを要求する。** ウォレット画面の履歴、「鳴動中のセッションを新しい順に1件」といった復旧ロジックは、
  絞り込み・並び替え・件数制限がそのまま欲しい。drift なら型安全な SQL 一発で、hive のように全件ロードして Dart 側で
  ソートする必要がない。
- **テストが本物と同じコードパスを通る。** `NativeDatabase.memory()` により、リポジトリのテストが実機と同一の
  SQLite 実装に対して走る（`flutter test` のホスト側でそのまま動くことを確認済み）。モックではなく実データベース。
- **お金が絡むのでトランザクションが要る。** 「セッション確定 → コイン減算 → おじさんの累計加算」は不可分でなければ
  二重課金や取りこぼしになる。drift のトランザクションでまとめている。
- **スキーマ変更に耐える。** Phase 2 でカード人質・課金明細・証拠ログが増える。マイグレーションの手段が最初からある方が安い。
- isar は現在メンテナンス状況が不安定であること、hive は上記のクエリ／トランザクション要件に対して薄すぎることから見送った。

drift のコード生成物 `lib/data/database.g.dart` はリポジトリにコミットしている（CI でも生成不要）。
スキーマを変えたら:

```powershell
dart run build_runner build
```

現在のスキーマは **v7**。

- **v1 → v2**：`alarm_rows` と `alarm_session_rows` に `grace_minutes`（既定 1）を追加。
  既存の行はすべて「猶予 1 分」＝従来と同じルールで書かれているので、移行によって過去の
  セッションの損失額が変わることはない。
- **v2 → v3**：お庭の 2 テーブル `garden_placement_rows`（配置済み）と
  `garden_inventory_rows`（手持ち）を追加。**移行では空のまま作る**だけで、初回配布は
  `GardenRepository.grantInitialIfNeeded` が行う。こうすると更新してきた既存インストールも
  新規インストールと同じ無料アイテムを受け取る。配布済みフラグは shared_preferences
  （`garden.initialGrantDone`）にあるので、庭を意図的に空にしても再配布されない。

- **v3 → v4**：アラーム v2 仕様のスキーマ変更を**一度にまとめて**行う。`alarm_rows` に
  スヌーズ（間隔・上限回数）・`sound_id`・覚悟のスヌーズ罰・寝坊時連絡先（JSON 1列）、
  `alarm_session_rows` に `wake_check_resolved`・スヌーズ履歴（JSON）・`current_ring_at_ms`、
  そして `contact_event_rows` を追加。
  追加した列はすべて nullable か、既存の行が書かれたときのルールを既定値にしている
  （スヌーズなし・同梱のベル・抽選なし）ので、過去のセッションの損失や成否は変わらない。
- **v4 → v5**：v4 が唯一取りこぼしたもの。`alarm_session_rows` に
  `kakugo_snooze_penalty` と `kakugo_snooze_resets_clock` を追加する。v4 はこの2つを
  **アラーム側にだけ**足していたため、セッションが凍結する覚悟のスナップショットが
  「鳴った時点の条件」を覚えられなかった。どちらも nullable で、読めない行は
  「スヌーズは無料・時計は止まらない」＝段階B以前のルールになるので、
  やはり過去のセッションの損失や成否は変わらない。
- **v5 → v6**：連絡帳 `contact_book_rows` を追加。**空のまま作るだけ**で、ほかの列は
  一切触らない。アラームの連絡先は JSON 1列のままなので、移行しても「誰に連絡するか」は
  変わらない（旧形式の読み方は上の「寝坊時の連絡設定（個人宛）」を参照）。
  アラーム→連絡帳の**外部キーは張っていない**：連絡帳から消しても、アラームが
  持っている控えでそのまま連絡できることが設計の目的なので。
- **v6 → v7**：実送信フェーズ1のスキーマ変更。`alarm_rows` に `oversleep_share`（共有の JSON 1列）
  と `oversleep_trigger_minutes` を追加し、`discord_webhook_rows` を作る。
  v6 の行はすべて書かれたときの規則どおりに読める：**share が null は「どこにも共有しない」**
  ＝ v6 のアラームがしていたこと、**送信タイミングが null なら連絡先の blob から読み出す**
  ので「猶予後7分」のアラームは7分のまま。新しいテーブルは空で作るので、
  共有先を持っていなかったアラームが勝手に持つこともない。過去のセッションの損失や成否は変わらない。

`test/data/migration_test.dart` が v1・v2・v3・v4・v5・v6 のスキーマを手で作って移行を通し、
既存の行が変わらないことと新しいテーブル・列が書けることを検証している。

### 実機で確認すべきこと（**未実施**）

初回起動時に通知権限とアラーム権限（「アラームとリマインダー」）の許可を求める。
電話と SMS の権限は、それぞれのトグルを ON にしたときに出る。
両方許可した上で、次の項目を確認する。

1. **画面 OFF・ロック中に指定時刻に鳴る。** full-screen intent で鳴動画面がロック画面の上に出ること。
   `flutter run` した状態で 2 分後のアラームを設定し、画面を消して待つ。
2. **鳴動中にアプリをスワイプで殺しても音が続く。** 鳴っている最中にタスク一覧からアプリを消し、
   音が止まらないこと（foreground service）。通知をタップして鳴動画面に戻れること。
3. **「解除」以外では止まらない。** 通知をスワイプしても、戻るボタンでもホームボタンでも音が止まらず、
   起床確認をクリアしたときだけ止まること。通知に停止ボタンとスヌーズが出ていないこと。
4. **再起動後の復帰。** 鳴動中にアプリを殺して開き直すと鳴動画面に戻ること。
   端末の日時を 60 分以上進めてから開き直すと、失敗として自動確定されリザルトが出ること。
5. **損失が予定時刻から数えられていること。** 通知を無視して 3 分後にアプリを開き、
   すでに 3 分ぶん燃えていること（開いた瞬間から 0 ではない）。

段階Dで増えた、**実機でしか確かめられない**もの：

6. **実在のメールアカウントで「テスト送信」が届く。** Gmail なら 2段階認証 →
   アプリパスワードを作り、送信元アドレスと 16 文字を入れて押す。自分の受信箱に
   「【Wake or Pay】テスト送信」が来ること。
7. **他人の番号に SMS が届き、電話が鳴り、スピーカーになる。** エミュレータでは自分自身と
   `dumpsys` の状態までしか見えない。**通話の音声が本当にスピーカーから出るか**は、
   メーカー独自の telephony スタックの上でしか確かめられない。
8. **バックグラウンド発火が省電力設定の下でも起きる。** エミュレータには Doze の
   メーカー独自実装が無い。`allowWhileIdle` と `exact` は指定してあるが、
   Samsung / Xiaomi などでは電池の最適化を外す必要があるかもしれない。

補足：メーカーによってはバッテリー最適化を無効にしないと鳴らない（dontkillmyapp.com 参照）。

**段階D もエミュレータ（AVD `wop`）で通しで確認済み。**

- **メール**：プロフィール → メール送信設定でプリセット（Gmail でホストが埋まり、
  フィールドが灰色になる）→ カスタムに戻して到達しないホストを入れ、アドレス・ユーザー名・
  アプリパスワードを入れて「テスト送信」。`送信できませんでした：通信エラー` が出て、
  パスワード欄は「保存済み（変更するときだけ入力）」になった。
  `run-as … shared_prefs/` を直接見て、**`FlutterSharedPreferences.xml` にパスワードが

  grep しても平文が出ないことを確認した。

  `SEND_SMS` のダイアログが出る。発火時刻に `content://sms` に `type=2`（送信済み）の行と

  （段階D2 時点の文言）。
- **電話**：`CALL_PHONE` のダイアログののち、発火時刻に発信。`dumpsys telecom` で

- **バックグラウンド発火**：鳴動開始後にアプリのプロセスを kill してから発火時刻を跨ぐと、

  バックグラウンドからは発信しないという設計どおり。そのあとアプリを起動し直しても
  **2通目は出ない**（claim が効いている）。

上の 4 つはデバッグビルドで確認したもの。**リリース APK でも**起動・プロフィール →
メール送信設定・アプリパスワードの保存（「保存済み」に変わる）まで通した——
R8 の難読化が `flutter_secure_storage` を壊していないことの確認で、段階C で通知アイコンが
リソース圧縮に削られていた件と同じ種類の事故を見るため。リリース APK の

## 既知の制約

- **Discord 連携には連携サーバーが要る**（段階G から**両方の機能**が）。コード交換には
  クライアントシークレットが要り、APK に埋めたシークレットはシークレットではないため。
  このリポジトリのビルドはデプロイ済みの Worker（`kDiscordExchangeEndpoint`。上の
  「連携サーバー（重要な変更）」）を指しているので、そのまま動く。自分のフォークを配るなら
  自分の Worker の URL に書き換えてビルドし直す必要があり、`kDiscordExchangeEndpoint` を
  空にしてビルドした場合は両方が名指しで断る（Webhook を手動で登録する経路はもう無い）。
- **Discord アプリの中では認可できない。** Discord の Android アプリは
  `discord.com/oauth2/authorize` も `discord:` スキームも intent-filter に持っていない
  （実機の `pm query-activities` で確認。上の「段階Gで直したこと」の 2 番）。
  だから認可はブラウザで行う。**戻り**は App Links なので、承認した瞬間にアプリに戻る。
- **App Links の検証は署名証明書に紐づく。** リリース用キーストアを作ったら、
  `worker/wrangler.toml` の `ANDROID_CERT_SHA256` を同じコミットで差し替えること。
  ずれても壊れはしないが、戻るときにブラウザのページが一瞬見える。
- **チャンネル名は取れない。** Webhook の `channel_id` から人が読む名前に変えるには
  Bot をサーバーに入れるか `guilds.members.read` が要る。ラベルを綺麗にするために
  もっと怖い同意画面を出すのは割に合わないので、表示名は**サーバー名**で止めている。
- **Discord で連携できるのは 1 つの流れずつ。** ブラウザが開いている間、
  ボタンは押せなくなる。コールバックのスキームは 1 つしかないので、2 つ目の流れは
  1 つ目のリダイレクトで解決されてしまう。
- **ストリーミング音源（YouTube 等）には対応しない。** 理由は 2 つ。(1) **鳴動の信頼性**：
  目覚ましは機内モード・圏外・通信障害・ログイン切れ・広告の割り込みのいずれでも必ず鳴らなければ
  ならないが、ストリーミングはそのどれでも無音になりうる。(2) **利用規約**：各サービスは
  バックグラウンド再生や音声の抽出・再配布を規約で禁じている。端末内のファイルを
  アプリ領域にコピーして使う方式だけを提供する。
- **`SEND_SMS` は Google Play をまず通らない。** Play の SMS/通話ログ権限ポリシーは、
  この権限を**既定の SMS アプリなど限られた用途にしか認めない**。目覚ましは該当しないので、
  **このアプリの配布は sideload（APK を直接入れる）前提**。`CALL_PHONE` も
  「発信を伴う」旨の説明が要る。Play に出す日が来たら、SMS の経路を落とすか、
  ユーザーに SMS アプリを開かせる形（`ACTION_SENDTO`）に替えることになる——ただし
  後者は**寝ている本人がタップしないと送られない**ので、この機能としては別物になる。
- **スピーカーフォンはベストエフォート。** 通話の音声経路を決めるのは telephony スタックで、
  「必ずスピーカーになる」API は存在しない。0.5秒おきに20回試して、駄目ならそのまま
  （耳元で鳴る通話でも、起こせてはいる）。**エミュレータでは
  `dumpsys telecom` が `ActiveSpeakerRoute` に入ることを確認したが、実機のメーカー独自
  スタックでは未検証。**
- **通話中は発信側の画面（システムのダイヤラ）が前面に出る。** 仕様には「鳴動画面は前面のまま」
  とあるが、`ACTION_CALL` は Android の in-call UI を起こすので、そのあいだ鳴動画面は
  その下になる。通話が終われば鳴動画面に戻り、アラームも鳴り直す。**アプリ側から抑えられる
  挙動ではない。**
- **`READ_PHONE_STATE` が無いと、通話中にアラームが止まらない。** 発信そのものは通る。
  通話の開始・終了が拾えないだけで、その場合はアラームが鳴りっぱなしのまま通話になる。
- **本物のチャンネルへ投稿が届いたところまでは未検証。** 自動テストはすべてフェイクの
  HTTP クライアント越しで、実在の Webhook に投稿したことはない（テストから他人の
  チャンネルに投稿しないため）。エミュレータでは、存在しない Webhook URL にテスト送信して
  Discord から **HTTP 404 が返る**ところまで確認してある。つまり経路は通っていて、
  あとは URL が正しいかどうかだけ。テスト送信ボタンが、そこを人間が確かめるための経路。
- **`-no-audio` のエミュレータでは TTS がアラーム音に重なるかを確認できない。**
  読み上げが**実行されている**ことは確認済み（`logcat` の `GoogleTTSServiceImpl` に
  ja-JP の合成要求が各キューぶん出る）。`speak(focus: false)` はオーディオフォーカスを
  一切要求しないため理屈の上では重なるはずだが、**実際に「アラームが鳴り続けたまま
  読み上げが聞こえる」ことは音の出る端末でしか確かめられない**。ここが段階Bで残った
  唯一の未検証点。
- **録音の再生とマイク権限ダイアログは未検証。** 録音そのもの（`record`、AAC/m4a）は
  エミュレータで録音→停止→「録音あり」まで動作した（`RECORD_AUDIO` は `record_android` の
  マニフェストからマージされるので宣言は不要）。再生は `-no-audio` のため音が出ず、
  権限ダイアログは `pm grant` で先に許可してしまったため出していない。
- **連絡帳の並び順は日本語の照合順序ではない。** Dart の文字列比較（UTF-16 コードユニット順）
  なので、よみがなを入れればあいうえお順になるが、よみがな無しの漢字はコードポイント順に並ぶ。
  濁点・半濁点・長音の扱いも辞書順とは違う。`intl` の照合や独自のキー正規化は入れていない。
- **あなたの名前が未設定だとデフォルト文面の主語は「Wake or Pay の利用者」になる。**
  文面の主語は利用者自身（寝坊した人）なので、ヘッダーのアイコン → プロフィール →
  「あなたの名前」で入れておくと「山田花子 さんは 07:00 の…」になる。連絡先の名前が
  主語になることはない。Discord の投稿でも同じで、名前も Discord ユーザーIDも無ければ
  「Wake or Pay の利用者 が寝坊をしています！」になる。
- **共有を空にしても録音ファイルは残る。** 共有先のトグルを全部外して共有そのものを捨てた
  場合、アプリ領域の録音ファイルは孤児として残る。「削除」を押したときだけファイルも消える。
- **本物のメールサーバー宛の送信は未検証。** 自動テストはすべてフェイクの transport 越しで、
  エミュレータでの確認は**到達しないホスト（127.0.0.1:587）**に対して「テスト送信」を押し、
  `送信できませんでした：通信エラー` が出るところまで。つまり設定の保存・パスワードの
  暗号化保存・送信の呼び出し・失敗の表示までは通っていて、**実在の Gmail アカウントで
  受信箱に届いたことは確認していない**（テストから他人のアドレスに送らないため）。
  そこを人間が確かめるための経路が「テスト送信」ボタン。
- **メールのデフォルト文面は件名と本文で `【Wake or Pay】` が重なる。** 件名は
  「【Wake or Pay】寝坊のお知らせ」で固定、本文のデフォルトも先頭に同じタグを持っている
  （SMS と本文を共有していた頃の名残）。害は無いが冗長で、直すなら文面の仕様ごと。
- **SMS の分割はプラットフォーム任せ。** `divideMessage` で切って multipart で送るので、
  日本語（UCS-2、1通70文字）の長いカスタム文面でも切れないが、**受信側での結合は
  キャリアと端末次第**で、まれに分割されたまま届く。
- **`shake` は実機の加速度センサーで未検証。** 閾値 12 m/s² と 0.5 秒の途切れ許容は
  `ShakeDetector` の単体テストと注入サンプルによるウィジェットテストで検証済みだが、
  実際の端末の生の加速度データに対しては未調整。エミュレータでは振れない。
- **サウンドのプレビュー再生と端末内ファイルの取り込みは実機で未検証。**
  ロジックはフェイク越しのテストで検証済みだが、`audioplayers` の実再生と
  `file_picker` の実ダイアログはエミュレータ／実機で通していない。

- **復旧経路（60分の安全弁）の修正は単体テストのみで検証済み。** エミュレータでの確認は
  この修正より前のビルドに対して行われたため、修正後の挙動は端末上で観測されていない。
- **物理実機での確認は未実施**（確認したのはエミュレータのみ）。メーカー独自の省電力挙動は
  エミュレータでは再現しない。
- **`alarm` パッケージが旧来の Kotlin Gradle Plugin を適用している。** ビルド時に Flutter が
  「将来のバージョンではビルドが失敗する」と警告する。現在の Flutter 3.47.1 ではビルド成功。
  パッケージ側の Built-in Kotlin 対応待ち。
- **メーカー独自の省電力設定。** Samsung / Xiaomi / OPPO などではバッテリー最適化を無効にしないと
  鳴らないことがある（dontkillmyapp.com）。アプリ内での案内は未実装。
- **`USE_FULL_SCREEN_INTENT` は Google Play の審査対象。** 目覚まし用途としての正当性説明が必要。
- 鳴動中の再スケジュールは行わない（`Alarm.set` が鳴動中のアラームを置き換えてしまうため）。
  起動時の `rescheduleAll` は `Alarm.isRinging` を見て鳴動中のものを飛ばし、繰り返しアラームの
  再武装は解除時（`AlarmService.stopRinging`）に行う。
- 鳴動通知のアイコンは指定していないため、アプリアイコンが使われる（`alarm` パッケージの
  フォールバック）。アプリ自身の通知（スヌーズ中・寝坊時連絡）は
  `res/drawable/ic_stat_notify.xml` を使う。`flutter_local_notifications` はアイコンを
  **`drawable` だけ**から探すので、`mipmap` にあるランチャーアイコンは指定できない。
  さらにこのアイコンは**実行時に名前で引かれる**ため、リリースビルドのリソース圧縮からは
  参照が見えない。`res/raw/keep.xml` で保持を明示していないと削られ、通知が
  `invalid_icon` で全部消える（しかも `SafeNotifier` が握り潰すのでエラーも出ない）。
- ローカライズ基盤（arb）は未導入。文言は日本語のハードコード。
- **お庭の絵はすべて仮**（単色図形＋絵文字）。上の「プレースホルダーの差し替え方針」を参照。
- **お庭のドロップ位置は指を置いたセルが左下**になる。2×2 のアイテムは指の位置から右上に伸びるので、
  見た目より半セルぶんずれて感じることがある。1×1 では起きない。
- **模様替えに「元に戻す」はない**（仕様どおり）。完了を押さずに戻れば下書きごと捨てられる。
- **地面から棚に戻したアイテムは成長がリセットされる。** 配置 ID ごと消えるので、置き直すと芽から。
- おじさんの小屋は地面の 8×6 の外（上のせり）に描いている。配置ルールをアイテムだけの話に
  保つための単純化で、仕様の「常設」は満たしている。
